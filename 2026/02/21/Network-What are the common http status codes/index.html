What are the common http status codes

Foreword

today, when the front-end and back-end separation architecture has become the mainstream, HTTP status code has become a key link in the communication between the client and the server. The success and failure of every request, jump and error, almost all rely on the status code to tell the client what happened. Understanding HTTP status codes not only helps us determine the result of the request, but also effectively guides the debugging process, improves the user experience, and optimizes the interface design.

This article will focus on the structure of HTTP status codes, common classifications, and the specific meanings of various status codes in detail, and combined with the actual development of the use of scenarios, to help you calmly deal with various types of HTTP communication problems.

Basic structure of HTTP status codes

the HTTP status code is a three-digit number, which is divided into five categories according to functions. The first digit of each category represents the type of status:

category Code description
1xx informational response, indicating that the request has been received, continue processing
2xx A successful response indicates that the request was successfully received, understood, and processed by the server
3xx redirect the response, indicating that further action from the client is required to complete the request
4xx client error, indicating that the request has a syntax error or the request cannot be completed
5xx server error, indicating that the server failed to complete a legitimate request

common status codes and their meanings

The following is a list of the most common status codes in actual development, organized by category:

1xx Informational Response

although not often handled directly, it is used in some special scenarios (such as HTTP long connections).

  • 100 Continue
    the client should continue to request, usually for preflight before large file uploads

2xx successful

  • 200 OK
    indicates that the request was successful, the most common response code.
  • 201 Created
    the request succeeds and a new resource is created, such POST return after creating a user
  • 204 No Content
    the request was successful but nothing was returned, often used for delete or update operations

3xx Redirect

  • 301 Moved Permanently
    the resource has been permanently moved to the new location and the search engine updates the address
  • 302 Found
    resources are temporarily redirected, the client should make the request using the original URI
  • 304 Not Modified
    resources are not modified, often used for browser cache control

4xx Client Error

  • 400 Bad Request
    Request format error, such as invalid or missing parameters
  • 401 Unauthorized
    unauthorized, need to provide authentication information
  • 403 Forbidden
    server denied access to resources, insufficient permissions or restricted access
  • 404 Not Found
    one of the most common errors is that the requested resource does not exist
  • 405 Method Not Allowed
    the request method is not allowed, for example, an unsupported one is used for an interface. PUT
  • 413 Payload Too Large
    request body too large, exceeding server limit

5xx Server error

  • 500 Internal Server Error
    an unexpected error occurred on the server, which is the focus of back-end troubleshooting.
  • 502 Bad Gateway
    gateway receives invalid response, common with reverse proxy server
  • 503 Service Unavailable
    the server is currently unable to process requests, possibly due to overload or maintenance
  • 504 Gateway Timeout
    upstream server response timeout

Summary

the HTTP status code is a “signal lamp” in the process of Web communication, instructing the client how to understand and process the response of the server. Developers need to be familiar with common status codes and their meanings in order to efficiently locate problems, design clear interface protocols, and improve system robustness.

Status codes are not only used for debugging, but are also closely related to the user experience. Such as reasonable use 404 page, exact return 403 prompting that users do not have permission helps to enhance the professionalism of the product.

Mastering the nature of HTTP status codes is not only the basic skill of development, but also an indispensable ability to build high-quality Web applications.
