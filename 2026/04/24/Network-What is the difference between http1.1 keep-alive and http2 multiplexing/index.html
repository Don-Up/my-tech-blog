What is the difference between http1.1 keep-alive and http2 multiplexing

Foreword

The HTTP protocol is the basis of data transmission on the World Wide Web, and with the improvement of the complexity and performance requirements of Internet applications, the HTTP protocol is also evolving. The Keep-Alive technology introduced by HTTP/1.1 greatly improves the connection reuse problem and reduces the overhead of frequently establishing TCP connections. In HTTP/2, Multiplexing is a core feature that further revolutionizes data transmission, enabling more efficient network utilization and lower latency.

This article will deeply analyze the working mechanism of Keep-Alive of HTTP/1.1 and multiplexing of HTTP/2, compare the differences between the two in detail, and help understand the evolution process of HTTP protocol performance optimization.

The working mechanism of HTTP/1.1 Keep-Alive

HTTP/1.0 is a short connection by default, that is, the TCP connection is closed immediately after a request response. The HTTP/1.1 standard introduces the default persistent connection mechanism – Keep-Alive, which allows the same TCP connection to be reused to send multiple requests and responses, avoiding repeated connection establishment and closure overheads.

Key Points

  • in the request or response header Connection: keep-alive (HTTP/1.1 default persistent connection, some servers still explicitly use this header).
  • The client and server send multiple requests and receive responses sequentially over the same TCP connection.
  • But the request is serial , You must wait for the previous response to finish before sending the next request.
  • The server or client can set a timeout or maximum number of requests, and close the connection after a timeout or limit is reached.

Advantage

  • reduce the overhead of TCP handshaking and hand waving.
  • Reduce latency and improve network efficiency.

Limitations

  • due to serial requests, there is a Head-of-Line Blocking problem: when a request response is blocked, subsequent requests must wait.

The working mechanism of HTTP/2 Multiplexing

HTTP/2 uses a single TCP connection at the transport layer, but allows multiple requests and responses to be multiplexed at the same time, known as multiplexing.

Key Points

  • over a TCP connection, transmissions are interleaved by splitting requests and responses into smaller frames.
  • Using streams to identify frames of different requests supports data exchange in parallel without blocking.
  • Request and response frames can be interleaved and sent simultaneously, greatly improving network utilization.
  • Resolved the problem of HTTP/1.x queue head blocking.

Advantage

  • dramatically reduce the number of connections and improve the resource utilization of servers and clients.
  • Reduce latency and improve loading speed.
  • Optimize the order of request processing through priority and dependency mechanisms.

HTTP/1.1 Keep-Alive vs. HTTP/2 Multiplexing

Impact in practical applications

after HTTP/1.1 uses Keep-Alive, the performance is significantly improved, but it is still limited by the number of TCP connections and queue head blocking. To bypass the restriction, browsers typically open multiple TCP connections to request resources in parallel.

HTTP/2 Multiplexing allows multiple concurrent requests and responses on a TCP connection, greatly reducing the number of connections and network latency, and has significant advantages for complex page loads.

the interviewer asked : What is the difference between HTTP/1.1 Keep-Alive and HTTP/2 multiplexing?

Answer:

the Keep-Alive of HTTP/1.1 allows the same TCP connection to multiplex multiple requests and responses, reducing the overhead of connection establishment and closure. However, requests are processed serially, resulting in queue header blocking. Browsers typically open multiple TCP connections to load resources in parallel.

While HTTP/2 allows multiple request and response frames to be interleaved and transmitted in parallel on a single TCP connection through a multiplexing mechanism, which solves the problem of queue head blocking, reduces the number of connections, and improves the network utilization efficiency and response speed. At the same time, HTTP/2 uses binary frame and header compression, and the overall performance is better.

Summary

HTTP/1.1 Keep-Alive is the implementation of persistent connection, which reduces the performance overhead caused by frequent connection establishment, but it still faces the limit of queue head blocking Because requests must be processed serially.

The multiplexing of HTTP/2 splits the request and response into independent frames to realize parallel transmission within the same connection, greatly improving the transmission efficiency and solving the bottleneck of HTTP/1.x.

Understanding the differences between the two will help us better understand the performance optimization brought about by the evolution of the HTTP protocol, and guide the front-end and back-end development to select appropriate technical solutions to improve the user experience.
