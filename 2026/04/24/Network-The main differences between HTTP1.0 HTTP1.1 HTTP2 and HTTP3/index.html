The main differences between HTTP1.0 HTTP1.1 HTTP2 and HTTP3

Foreword

HTTP(HyperText Transfer Protocol) is the cornerstone of modern Web communication. Since its release in 1991, the HTTP protocol has undergone multiple versions of iteration. Each upgrade aims to solve the shortcomings of the previous version in terms of performance, security, and concurrency to meet the growing needs of the Internet.

This article will compare HTTP/1.0, HTTP/1.1, HTTP/2 and the latest HTTP/3 in depth, and analyze the disassembly from the perspectives of connection reuse, data transmission mechanism, header compression, sequential blocking, and security to help you fully understand the key differences between each version.

Detailed Explanation of Version Evolution

HTTP/1.0: The earliest standardized version

HTTP/1.0 was officially standardized in 1996 and is the first public version of the HTTP protocol. It has the following characteristics:

  • each request establishes a new TCP connection, resulting in wasted resources and delays.
  • Connection multiplexing is not supported.
  • The response has no cache control capability and lacks a flexible Cache mechanism.
  • Only the most basic GET and POST methods are supported, and the scalability is poor.

HTTP/1.1: widely used upgrade

HTTP/1.1 was released in 1997 and addresses multiple performance and scaling issues with HTTP/1.0.

Key improvements:

  • introductionConnection: keep-alive realize connection multiplexing, multiple requests can reuse the same TCP connection.
  • Support Pipelining , multiple requests can be sent at the same time, but the responses must be returned sequentially.
  • Added cache Control (Cache-Control, ETag, Last-Modified).
  • Introduction Host the header supports virtual hosts.
  • Added more Request methods such as PUT, DELETE, OPTIONS.

Question:

  • although keep-alive is supported, Head-of-line blocking still exists.
  • The application of pipeline is less in practice, and the browser support is limited.

HTTP/2: Performance Optimization

HTTP/2 was officially released in 2015. It evolved from the SPDY protocol and completely changed the data transmission model.

Core features:

  • all communication takes place in one TCP connection, supporting true Multiplexing no head blocking occurs.
  • Introduction **Frame (Frame)**And Stream (Stream) concept, request and response are split into non-interfering frames.
  • Support head compression (HPACK) , which greatly reduces the transmission of duplicate head Information.
  • Support Server Push , the server can actively push resources.
  • The binary protocol replaces the text protocol of HTTP/1.x to improve the parsing efficiency.

Question:

  • multiple requests share a TCP connection, and TCP-level queue head blocking still exists.
  • You must rely on the underlying TCP transport layer, which cannot solve the overall blocking problem caused by connection packet loss.

Example structure:

HTTP/2 is not a traditional text format, but organizes data in the form of frames and cannot be viewed directly through telnet or curl.

HTTP/3: QUIC-based modern protocols

HTTP/3 is a protocol version based on Google’s QUIC protocol. Its goal is to completely solve the problem of TCP team head blocking and improve mobile terminal performance.

Main improvements:

  • no longer using TCP, but based on UDP + QUIC protocol transmission.
  • Each request has a separate stream , Really achieve non-blocking multiplexing.
  • Built-in TLS 1.3 Encryption simplify the handshake process, improve security and connection speed.
  • Fast connection recovery, especially suitable for mobile network scenarios.

Advantages:

  • faster connection establishment: With 0-RTT, zero latency recovery is possible after the first connection.
  • Packet loss only affects the current stream, which solves the transmission bottleneck of TCP under the shared connection.
  • Better mobile network compatibility (e. G. Continuous connection when IP changes).

Deficiencies:

  • UDP-based implementations may be blocked or not supported in some intermediate devices (e. G. Firewalls, proxies).
  • The implementation complexity is higher and the deployment cost is slightly higher.

interview answer

Question: Can you talk about the main changes and differences from HTTP/1.0 to HTTP/3?

Answer:

the evolution of HTTP from 1.0 to 3 is mainly to solve performance bottlenecks, concurrency restrictions, and security issues:

  • HTTP/1.0 : A TCP connection is established for each request, which cannot be reused and is inefficient.
  • HTTP/1.1 : The keep-alive and cache mechanisms are introduced to support piping, but are still limited by queue head blocking.
  • HTTP/2 : uses binary frame transmission, real multiplexing, header compression and server push to greatly optimize performance, but because it is still based on TCP, packet loss is still limited.
  • HTTP/3 : completely abandon TCP, use QUIC (based on UDP), and stream each request independently, truly realizing low latency, anti-packet loss, and high concurrent data transmission, especially suitable for modern Web scenarios.

Summary

the evolution of the HTTP protocol is a constant response to the needs of real-world Internet applications. From the initial serial text communication, to the high-performance transmission of multiplexing, to the QUIC-based low-latency encryption channel, HTTP is constantly breaking through its own bottleneck.

Understanding the features of each version not only helps us write higher performance and more secure applications, but also shows stronger professional ability in network tuning, architecture design and interview answering. In the face of the rapid development of modern browsers and service environment, the gradual landing of HTTP/3 will also become the front-end and full stack developers need to focus on the direction.
