What problems exist in the react15 architecture

Foreword

React is one of the current mainstream front-end libraries, and its architecture design is constantly evolving to meet complex application requirements. React 15 is an important early version of React, which lays the core foundation for React componentization and Virtual DOM. However, with the increasing complexity of application scenarios, the architecture of React 15 gradually exposes bottlenecks in performance and flexibility. This article will analyze the main problems of the React 15 architecture and lay the foundation for understanding the subsequent versions (such as the Fiber architecture of React 16).

React 15 Architecture Review

React 15 uses a synchronous virtual DOM tree comparison algorithm (Diffing algorithm), and the entire update process is performed synchronously, that is, one update task completes DOM changes as quickly as possible. Its core processes are:

  • when the state or property changes, the render method is triggered to recalculate the Virtual DOM.
  • Recursively compare the old and new Virtual DOM to generate the smallest DOM update patch.
  • These patches are executed synchronously to update the real DOM.

Although this mechanism is simple and direct and suitable for most scenarios, its defects gradually appear in large-scale complex UI and applications with frequent interaction.

React 15 architecture of the main problems

  1. synchronous rendering causes main thread to block

the update process of React 15 is synchronous and will not be actively interrupted during execution. If the Virtual DOM tree is large or changes a lot, the entire rendering process may cause the main thread to be occupied for a long time, affecting the page response and causing the stuck experience.

  1. Cannot interrupt and priority scheduling

React 15 does not support task interruption or task priority scheduling. Even if the user triggers a high-priority interaction event, the current rendering task cannot be paused, affecting the user experience.

  1. Long tasks cause page interaction to block

because the update process is not fragmented, complex updates will become long tasks, causing page jam and frame loss, affecting performance and user operation fluency.

  1. Lifecycle method call order and consistency issues

the lifecycle hook design of React 15 has some flaws, such componentWillMount and componentWillReceiveProps asynchronous rendering can introduce inconsistencies, leading to unpredictable errors in state management and side-effect handling.

  1. Missing error boundary

React 15 lacks an error boundary mechanism. When a subcomponent throws an exception, the entire component tree will crash, unable to catch the error locally and recover gracefully.

  1. Complex component state management

due to the lack of Fiber architecture support, the component state update of React 15 is atomic and synchronous, which is not conducive to handling complex state chains and task splitting.

Summary

The React 15 architecture lays the foundation for Virtual DOM and componentization. However, due to its synchronous rendering mechanism and lack of task scheduling capability, it is difficult to meet the performance and response speed requirements of large applications. It has problems such as main thread blocking, inability to interrupt updates, imperfect Lifecycle methods, and lack of error boundaries. By introducing the Fiber architecture, React 16 solves these bottlenecks, implements asynchronous rendering and priority scheduling, and greatly improves performance and stability. Understanding the shortcomings of React 15 helps to understand the design concept and technological evolution of React 16 and beyond.

The interview answer

question: What is the problem with the React 15 architecture?

Answer:

React 15 uses synchronous virtual DOM rendering, and the entire update process is completed at one time, causing the main thread to be blocked for a long time, affecting page response and interaction fluency. It does not support task interrupt and priority scheduling, and cannot handle the need for interrupt rendering. The design of life cycle method has the problem of inconsistency and the lack of error boundary mechanism, which makes it difficult to capture and recover errors locally. These problems are evident in complex large scale applications. React 16 implements asynchronous rendering and priority scheduling through the Fiber architecture, effectively solving these bottlenecks.
