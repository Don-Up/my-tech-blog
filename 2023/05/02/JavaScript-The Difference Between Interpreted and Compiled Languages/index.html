The Difference Between Interpreted and Compiled Languages

foreword

in front-end development, JavaScript is often referred to as an “interpreted language”. However, under the optimization of modern engines (such as V8), its execution process is actually not the original kind of pure interpretation execution. At the same time, developers often understand “interpreted language” and “compiled language” as opposed to each other, but the terms themselves are not absolute classifications. This article will focus on these two concepts to help you understand the essential differences between them and the place of JavaScript in them.

Text

interpreted and compiled languages are not definitions of the language itself, the way the language is implemented . A language can be interpreted or compiled, depending on its runtime environment or engine implementation.

Features of compiled languages

before execution, the code is compiled once into machine code that the target machine can run directly, such as C, C ++, and Go. The advantage of this method is that the execution efficiency is high, but the disadvantage is that it lacks flexibility and cannot run the code dynamically.

The compilation process usually includes lexical analysis, syntax analysis, semantic analysis, optimization, generation of object code and other steps. After compilation will generate .exe or .o and other binary files, the runtime no longer depends on the source code.

Characteristics of Interpreted Language

Interpreted languages, on the other hand, do not go through a pre-compilation process, but are translated line by line by the interpreter into machine-understandable instructions and executed at runtime. Typical examples are Python and early JavaScript. The advantage of this approach is that the code can be executed dynamically, which is more flexible, but the execution efficiency is usually lower.

Early JavaScript was executed line-by-line by the browser’s built-in interpreter and was therefore classified as an interpreted language.

Is modern JavaScript interpreted or compiled?

Modern JavaScript engines such as V8 introduce * * just-in-time compilation (JIT) * * technology, JavaScript code will be compiled into intermediate bytecode before running, and then optimized into machine code. It combines the advantages of interpretation and compilation, both to quickly start execution and to improve performance through hot-spot code optimization.

Therefore, JavaScript is no longer a purely interpreted language, but a mixed-mode language that interprets and compiles in parallel. .

Interview answer demonstration

question: Is JavaScript an interpreted language? What is the difference between interpreted and compiled languages?

Example answer:

“Traditionally, JavaScript has been called an interpreted language because it was interpreted and executed line by line in the browser in the early days. However, current JavaScript engines (such as V8) use just-in-time compilation technology, which compiles JS into intermediate bytecode or even machine code at runtime to improve execution efficiency.

Interpretive languages execute code line by line at runtime, while compiled languages compile code into machine code before running. JavaScript is now a mixed model of interpretation and compilation, more precisely a dynamic language or JIT compilation language.”

summary

the essential difference between interpreted and compiled is that when and how code is translated into instructions that the machine can execute . JavaScript used to be a classic interpreted language, but with the development of engine technology, it has long been out of the scope of pure interpretation and execution, to a higher performance JIT compilation mode. Understanding this evolution process will help us to understand the execution mechanism of JavaScript more accurately, and it will also help us to make more professional expressions in the interview.
