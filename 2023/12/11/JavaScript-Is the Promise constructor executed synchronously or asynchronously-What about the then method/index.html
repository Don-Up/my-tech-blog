Is the Promise constructor executed synchronously or asynchronously-What about the then method

Foreword

understanding the timing of Promise execution is key to mastering asynchronous programming. In actual development, we often encounter the question: Why do some codes execute first and some codes execute later? Many people mistakenly think that as long as Promise is used, the code inside is executed asynchronously. But the truth is not. This article will focus on the Promise constructor and then the timing of the execution of the method is analyzed in depth to help you clarify the boundary between synchronous and asynchronous.

The Promise constructor is executed synchronously

when you create a Promise instance, the callback passed into the constructor is immediate execution and does not delay asynchronously.

then method is asynchronous (microtask)

unlike constructors, then the callback function of the method is pushed into the microtask queue and executed after the current macro task is completed.

the Promise constructor is executed synchronously, which means that when you create a Promise instance, the function you pass in will be executed immediately. This is a place that is easy to misunderstand. Many people think that as long as the Promise is asynchronous, it is actually wrong.

What’s really asynchronous is then method of the callback, that is, you call promise.then(() => {}) after that, the logic inside will not be executed immediately, but will be put into the microtask queue and will not be executed until the current synchronization code and synchronization task are completed.

To sum up, the constructor of Promise is synchronous, then is asynchronous, and its callback is arranged in the micro task queue, which takes precedence over macro tasks (like setTimeout).

Summary

The Promise constructor is executed synchronously, which means that the moment the Promise is created, the internal logic is already running. The callback of the then method is asynchronous, belongs to the microtask queue, and will be executed after the current call stack is empty. Mastering this distinction is essential for understanding how promises work, writing correct asynchronous logic, and avoiding common logic errors.
