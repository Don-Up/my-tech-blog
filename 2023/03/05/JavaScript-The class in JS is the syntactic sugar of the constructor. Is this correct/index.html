The class in JS is the syntactic sugar of the constructor. Is this correct

Foreword

introduced by ES6 class since the syntax, it has often been argued that classes in JavaScript are just syntactic sugar for constructors. This sentence is very important in understanding JavaScript language design and object-oriented programming. This article will analyze in detail the correctness of this statement, in-depth discussion. class the relationship and difference with the traditional constructor.

Parsing the meaning of “syntactic sugar”

grammatical sugar refers to a more concise, readable grammatical form provided at the language level, which essentially does not change the underlying behavior and mechanisms of the program at runtime.

In other words, class the syntax brings Object-Oriented Code closer to the way traditional OOP languages are written, but the operating mechanism is still based on prototypes and constructors.

The commonality of class and constructor

  • are essentially functions
    in JavaScript class is actually a special function, and the declared class behaves as a function at runtime.
  • Implementation of Inheritance Based on Prototype Chain
    whether it’s a constructor or a class inheritance is essentially done through the prototype chain.
  • Instance properties are defined by the constructor execution body
    constructor the properties defined in the function are the properties of the instance itself.
  • Method definition on prototype
    class the methods defined in the class are by default in prototype on, similar to the constructor prototype method.

Difference between class and constructor

  • strict mode
    class strict mode is enabled by internal default, constructor default is not.
  • Must be invoked with new
    class direct calls are not allowed and must be made with new otherwise, it will be wrong. The constructor can be called directly, and the binding this it may not be correct.
  • Method not enumerable
    class the defined method is not enumerable on the prototype, and the constructor prototype method is enumerable by default.
  • Grammar is more standardized and clear
    class syntax supports inheritance ( extends ), parent class method call ( super), static methods, etc., with a more rigorous structure.
  • Cannot be called in advance
    in class must first call super() in order to access this , the constructor does not have this restriction.

Summary

so to speak, class it is the syntactic sugar of the constructor, which encapsulates a lot of tedious inheritance logic and makes the code clearer and easier to maintain, but the underlying operating mechanism is still based on functions and prototypes.

Interview answer demonstration

question: Some people say that classes in JavaScript are syntactic sugar for constructors. Is this correct? Why?

Example answer:

“This statement is basically correct. In JavaScript. class is the syntactic sugar introduced by ES6, which encapsulates the implementation mechanism of traditional constructor and prototype chain inheritance with a clearer syntax. The bottom layer is still functions and prototypes, class just make object-oriented writing more standardized and concise. At the same time, class there are additional restrictions and features, such as the default strict mode, the need to use newCalls, methods are not enumerable, etc., making the code safer.”

summary

understanding class and the relationship between the constructor, help to master the JavaScript Object-oriented programming. Although class provides a more elegant syntax, but it does not change the essential mechanics of the language. Familiarity with both helps to write high-quality, maintainable code.
