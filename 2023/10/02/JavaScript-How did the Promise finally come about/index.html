Interview answer

finally is a method provided by the Promise to execute a callback after the task succeeds or fails. This callback does not receive any parameters and is mainly used to do some finishing actions, such as closing loading or clearing temporary data.

The timing of its execution is after the execution of then or catch, regardless of whether the previous is resolve or reject,finally will be called. And finally does not affect the value passing of subsequent Promise chains. For example, if the Promise was originally resolve(‘OK’), after executing finally, the’ OK ‘will still be passed to the following then.

However, there is one point to note: If finally throws an exception inside itself or returns a rejected Promise, the whole chain will be interrupted and the catch branch will be entered. This is the actual development of special attention.

In addition, finally can also be implemented by then + catch simulation. The principle is to execute callback in both successful and failed branches, and then continue to pass the original value or error.

In actual work, the scene where I use finally most is to close the loading state after the asynchronous request ends. Whether the request succeeds or fails, finally will be called, which is very suitable for cleaning up the loading state.

Summary

The finally method of Promise is a small but powerful tool in asynchronous programming. It can make the code more concise and clear, especially suitable for unified resource cleaning and UI update operations after the completion of asynchronous tasks. It does not by itself change the value-passing logic of the Promise, but it can also affect the error handling flow if used incorrectly. Understanding its principles and behavioral characteristics will help you write more robust and maintainable asynchronous logic.
