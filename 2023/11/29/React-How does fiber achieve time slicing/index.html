How does fiber achieve time slicing

Foreword

as the complexity of Web applications increases, page rendering tasks become heavier and heavier, and traditional synchronous rendering often blocks the main thread, causing interface stutter and user interaction delay. React introduces the “Time Slicing” technology in the Fiber architecture, which uses the browser’s idle Time to split the rendering task into multiple small blocks and execute them in batches, thus improving the page response speed and smoothness.

This article will analyze in detail the principle, core mechanism, and scheduling process of Fiber to implement time slicing, along with code examples and process descriptions, to help readers understand how Fiber makes React rendering more efficient and does not block the main thread.

What is time slicing?

Time slicing refers to dividing a large task into several small tasks. Each small task is executed within a certain time slice. After execution, it is suspended, giving the main thread to the browser to process high-priority tasks such as user input and animation, and then continuing to execute the remaining tasks when idle.

Time slicing allows the browser to render large tasks while keeping the interface responsive and improving the user experience.

How does Fiber support time slicing?

1. Split Fiber tasks into Unit of Work

the Fiber architecture breaks down the coordination of the entire virtual DOM tree into “unit tasks” corresponding to Fiber nodes “. Each unit task is responsible for updating the node and its child nodes.

Unit task granularity is fine enough to ensure short execution time.

2. Use your browser’s free time to perform tasks

Fiber through the idle time scheduling API provided by the browser (suchrequestIdleCallback ) Or, based on the timestamp and the remaining time of the task, execute the unit task when the main browser thread is idle.

The scheduling logic will judge whether the current idle time is enough to execute the next unit task, and if the time is not enough, the execution will be suspended, and the remaining tasks will be suspended to wait for the next idle time.

3. Execution can be interrupted and resumed

Fiber saves the pointer of the unit task currently being executed through the linked list structure. After executing a small piece of task each time, the current execution state can be saved and the execution will continue when the idle time is restored next time.

This mechanism of interrupting and resuming is the core of time slicing, which realizes the execution of tasks in slices.

Scheduling Process Analysis of Fiber time slicing

the rendering process is mainly divided into two phases: the Render phase (coordination phase) and the Commit phase (Commit phase). Time slicing occurs primarily in the Render phase.

  1. Schedule Start : React starts the schedule and obtains the initial unit task pointer.
  2. Execute Unit Tasks : Call performUnitOfWork handles the coordination of the current Fiber node.
  3. Check Idle Time : Use deadline.timeRemaining() determine if there is enough time to perform the next cell task.
  4. Task Pause : If the idle time is insufficient, suspend the scheduling and save the remaining task status.
  5. Wait Idle : through requestIdleCallback register the next idle callback and continue with the remaining tasks.
  6. All done : after all Fiber nodes are coordinated, enter the Commit phase to update DOM synchronously.

Relationship between Fiber time slicing and priority scheduling

time slicing allows large tasks to be split up, but it also needs to ensure that important tasks are completed first. Fiber combines priority scheduling to assign different priorities to different tasks. For example, user input and animation tasks have the highest priority and are scheduled first.

Time slicing ensures that even large low-priority tasks can be split into smaller segments to avoid blocking more important tasks and keep the UI flowing smoothly.

Advantages of Fiber time slicing

  • avoid occupying the main thread for a long time and improve page responsiveness.
  • Support task can be interrupted and resumed, improve scheduling flexibility.
  • Combined with priority scheduling, high priority tasks are executed first.
  • Lay the foundation for advanced features such as React concurrency mode and Suspense.

Interview answer example

question: How does Fiber implement time slicing?

Example answer:

the Fiber architecture splits coordination into many independent unit tasks, each corresponding to a Fiber node in the Virtual DOM. Take advantage of the browser idle time API (e. G. requestIdleCallback ),React performs these unit tasks when the main thread is idle.

During execution, the remaining idle time will be detected in real time. If the time is insufficient, the scheduling will be suspended, the current execution state will be saved, and the execution will resume after the next idle time, thus realizing the fragmented execution and interruption of the task. This mechanism avoids blocking the main thread for a long time and improves the response speed and user experience of the page.

At the same time, Fiber combines task priority scheduling to ensure that key tasks are completed first. Incremental execution and non-blocking scheduling of rendering tasks are implemented as a whole.

Summary

Fiber implements time slicing by fine-grained splitting and coordinating tasks and combining with the browser idle time API. Time slicing makes React rendering no longer a single, long-blocking synchronization process, but is split into multiple small tasks that can be interrupted and recovered, which are executed step by step when idle, greatly improving the availability of the main thread and the UI response speed.

This technology provides a solid foundation for React’s modern asynchronous rendering and Concurrency patterns, and is key to React’s performance optimization. Understanding the principle of Fiber time slicing helps developers to better optimize the performance and user experience of React applications.
