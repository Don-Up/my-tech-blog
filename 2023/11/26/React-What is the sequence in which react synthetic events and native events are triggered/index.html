What is the sequence in which react synthetic events and native events are triggered

Foreword

in React application development, understanding the event mechanism is the key to improving code quality and troubleshooting. React introduces a Synthetic Event system, which encapsulates events through Event delegates and Event objects. However, in real projects, we often use both React synthetic events and browser-Native event listeners.

At this time, it is particularly important to understand the trigger sequence of React synthetic events and native events. This article will systematically explain the triggering mechanism, chronology and impact of the two, helping you to understand and use events correctly, and avoid potential event conflicts and interactions that do not meet expectations.

Event system background knowledge

browser Native Events

the browser’s event system is divided into three phases: the capture phase, the target phase, and the bubbling phase. Event listeners can be triggered during the capture phase or the bubbling phase, the default addEventListener bound is bubbling phase listening.

React synthetic event system

React composite events unify the representation of cross-browser events and adopt the event delegation mechanism. React will be in the root container of the application (such document or root node) uniformly binds a few native event listeners to listen for native events in the capture or bubble phase.

When a native event is triggered, React captures the event in the root container, finds the corresponding component based on the event path, creates a synthetic event, and triggers an event callback on the corresponding component.

Triggering sequence of React synthetic events and native events

1. The location and timing of the React event binding.

React 17 and later bind the native listener of all synthetic events to the root DOM node mounted by the React application (usually root ), and the default binding in capture phase .

This means that the React listener will be triggered during the native event capture phase.

2. The binding location and phase of the native event listener.

Native event listeners are typically passed through addEventListener add, you can specify the capture phase (the third parameter is. true ) or the bubbling phase (default false ) binding.

3. Rules for the trigger sequence

assume the following binding:

  • React synthesized event listener, bound to the root node capture phase (React by default)
  • native event listeners, bound to the capture or bubbling phase of a DOM element

The order of triggering depends on three phases of event propagation:

  • event propagation from document root node to target element as capture phase
  • reach destination node
  • return the root node from the target node to the bubbling phase

the React composite event listener is bound to the root node capture phase and is triggered first, while the native event listener determines the trigger time based on the binding phase and node location.

Impact and Precautions

  • the React event takes precedence over the target element’s native event capture listener, which means you can call stopPropagation preventing subsequent native capture event execution.
  • Because The React event is bound to the root node, if the native event is bound to the child element capture phase, it is usually triggered later than the React composite event.
  • When debugging event firing order and blocking event propagation, you must understand the binding nodes and phases of the event listener.
  • The interrupt of The React event execution does not affect the triggering of the native event listener (browser mechanism limitation), but stopImmediatePropagation can prevent subsequent listener execution.

Interview answer: What is the trigger sequence of React synthetic events and native events?

The synthesized event listener of React 17 and later versions is bound to the capture phase of the React root container, so the synthesized event will be triggered first. If the native event listener is bound to the capture or bubbling phase of the target element, it will be triggered after the React event, and the order of triggering depends on the binding phase and DOM level of the listener.

In short, The React synthetic event listener executes in preference to the target element’s native event listener.

Summary

the order in which React synthetic events and native events are triggered is mainly affected by the event propagation phase (capture/bubble) and the location of the listener binding node. React 17 + binds the composite event listener to the root node capture phase, so that the composite event is triggered first.

Understanding this can help us design event processing logic more rationally, avoid event conflicts, and improve application robustness and user experience.

In-depth understanding of the interaction mechanism between React and native events is an important step to improve the frontend development capability.
