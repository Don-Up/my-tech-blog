Which apis of the hooks are mapped for the lifecycle of class components

Foreword

React has evolved from the initial class component development model to a new model with function components and Hooks as the core. Class components help developers manage the process of mounting, updating, and uninstalling components through rich Lifecycle methods, while function components implement similar functions through Hooks. Understanding the mapping between the lifecycle of class components and Hooks helps to better migrate from class components to function components and to master the core usage of Hooks.

This article reviews the common Lifecycle methods of React components in detail, maps them to the Hooks API in the function component, and combines examples to help understand the equivalence between the two.

Class Component Lifecycle Review

the lifecycle of a React component can be divided into three stages:

mount phase:

  • constructor
  • static getDerivedStateFromProps
  • render
  • componentDidMount

update phase:

  • static getDerivedStateFromProps
  • shouldComponentUpdate
  • render
  • getSnapshotBeforeUpdate
  • componentDidUpdate

unloading phase:

  • componentWillUnmount

among them, constructor and render almost a necessary life cycle, getDerivedStateFromProps and shouldComponentUpdate mainly used for status and performance control, componentDidMount , componentDidUpdate , componentWillUnmount this is a critical time for side effect management.

Hooks Correspondence Analysis

class Component Lifecycle corresponding Hooks API role and Description
componentDidMount useEffect(() => { ... }, []) perform side effects only when the component is mounted, equivalent componentDidMount .
componentDidUpdate useEffect(() => { ... }) execute side effects when dependencies change, corresponding to the update phase.
componentWillUnmount useEffect(() => { return () => { ... } }, []) the cleanup function is called when the corresponding component is unloaded to release resources.
getDerivedStateFromProps useState + useEffect need to pass manually useEffect listen for props changes and update the state.
shouldComponentUpdate React.memo + useMemo by React.memo controls whether the function component is re-rendered, useMemo cache calculations.
getSnapshotBeforeUpdate no direct correspondence Can be passed useLayoutEffect approximate implementation to get a snapshot of the DOM before it was updated.

Key Hooks API details

useEffect

useEffect is the core Hook for most side-effect management lifecycles in alternative class components. By passing in different dependency arrays, you can implement different logic only when you mount, update, or uninstall.

Empty dependent array [] indicates that it is only executed on Mount and Unmount.

useLayoutEffect

useLayoutEffect similar useEffect , but its callback is executed synchronously after all DOM changes are completed and before the browser draws, similar getSnapshotBeforeUpdate and componentDidUpdate the synchronous operation of.

React.memo and useMemo

React.memo used to wrap function components to control whether the components are re-rendered due to props changes, corresponding to class components.shouldComponentUpdate . useMemo used to cache calculation results and optimize performance.

Summary

understanding the relationship between the lifecycle of React class components and the Hooks API is the basis for mastering the development of function components. Hooks replace the tedious Lifecycle Functions of class components in a more flexible and concise way, while giving developers more fine-grained control. Mastering this mapping helps developers migrate class components to function components more smoothly and write more elegant and maintainable React code.
