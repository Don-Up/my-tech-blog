Why is it recommended not to use index as the key in react loop rendering

Foreword

in React, list rendering is a common requirement when building dynamic interfaces. In order to improve rendering efficiency and maintain component state, React requires a unique key property. Although many developers are used to using array indexes index as key however, there are many potential problems with this approach that affect performance and user experience.

This article will elaborate on why it is not recommend to use index as key , what is the principle behind it, and provides correct practice suggestions and code examples to help readers write more robust and efficient React list components.

The Role of key in React

key is the unique identifier used by React to identify elements. It helps React to quickly locate which elements have changed, added, or deleted, thus avoiding unnecessary DOM operations and improving rendering performance.

When React re-renders the list, according key to match the old and new elements, if key ununique or unreasonable changes may cause React to incorrectly reuse or destroy components, resulting in side effects.

Why don’t you recommend use index as a key?

Use index key it is easy to cause problems in the following scenarios:

1. List order changes lead to error reuse.

When the list order changes (such as insert, delete, sort), the index-based key React mistakenly believes that the component has not changed and incorrectly reuses the component instance.

For example:

original list: [A, B, C] , corresponding to key [0, 1, 2]

new list after removing the first element: [B, C] , corresponding to key [0,1]

React will think that the key of the first element of the new list is still 0, and directly reuse the component (I .e. A) with the original key of 0 in the old list, resulting in the actual display of B as A state, resulting in confusion.

2. Component State disorder and side effects

the reuse of errors leads to a mismatch between the internal state of the component and the DOM state, such as form input errors, animation exceptions, and so on.

3. Performance waste

wrong reuse may cause React to misjudge nodes that need to be updated, resulting in unnecessary redrawing or destruction of reconstruction.

Suitable for scenarios where index is used as key.

Use the index only when the list content is fixed and will not be added or deleted, or when the list is statically displayed. key is acceptable.

Recommend practices

  • prioritize the unique identifier of the data, such as the database ID, UUID, and so on. key .
  • If there is no unique ID, you can generate a stable unique identifier, such as string concatenation.
  • Avoid using indexes in mutable lists key .
