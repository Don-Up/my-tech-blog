Why does useEffect only perform shallow comparisons when relying on arrays

Foreword

in the function component of React, useEffect is the core Hook for managing side effects. Its second parameter, the dependent array, determines how often the side-effecting function is executed. React uses shallow comparisons instead of deep comparisons when determining whether dependencies have changed.

Why does React not choose deep comparison? What are the design considerations behind this? This article will be detailed analysis useEffect the reasons for relying on shallow comparison of arrays and their advantages and disadvantages help us to better understand and use them. useEffect .

useEffect relies on the mechanism of shallow comparison of arrays.

React in execution useEffect the currently rendered dependency array is compared with the last rendered dependency array item by item, but the comparison method is shallow comparison , that is, by comparing the reference address ( Object.is ) Determine whether the two values are equal. As long as the reference address of the dependency is the same, React considers that the dependency has not changed. As long as the reference is different, it considers that the dependency has changed and executes side effects.

This shallow comparison behavior applies to basic data types as well as reference-type objects, arrays, and functions.

Why not make a deep comparison?

1. Performance considerations

Deep comparison requires recursively traversing all levels of the object and comparing each field, which consumes computing resources in complex nested objects or arrays, especially in scenarios where React renders and schedules frequently. Deep comparison brings significant performance overhead and reduces page response speed.

Shallow comparison by directly comparing the reference address, the time complexity is only O(n)(n is dependent on the array length), far better than the complexity of deep comparison recursion. This trade-off ensures stable and smooth React performance.

2. The design is simple and clear

shallow comparison conforms to React’s declarative design concept and immutable data flow idea. React encourages developers to use immutable data structures (immutable data), which return new objects with each data update, so that shallow comparisons are sufficient to determine whether dependencies have changed.

If the deep comparison is done automatically inside React, the details of the data changes will be hidden, which may cause the execution of side effects to become unpredictable and difficult to debug.

3. Avoid side effects of performing “magic”

if the dependency array contains complex data, deep comparisons may trigger side effects frequently, or cause Side Effect executions to spike due to some subtle change. Through shallow comparison, the triggering of side effects depends on the developer explicitly updating the dependent reference, which enhances the controllability of the code.

Challenges and Countermeasures Brought by Shallow Comparison

shallow comparisons of dependencies on reference types pose some challenges:

  • if the dependency is an object or an array, but the reference changes every time (even if the content is the same), the side effect will still be executed.
  • Anonymous functions that are common in function components can also be executed frequently if they are used as dependencies.

To avoid these problems, common coping strategies include:

  • Use useMemo cache objects and arrays to ensure reference stability.
  • Use useCallback cache functions to avoid function reference changes.
  • Split dependencies, relying only on essential basic types or stable variables.

react.useEffect the dependency array is only a shallow comparison, mainly based on performance and design principles. Shallow comparison avoids the performance consumption caused by deep recursive comparison by comparing the dependent reference addresses, and conforms to the design concept of React using immutable data. Shallow comparison makes the judgment of dependent changes efficient and controllable, avoiding frequent execution and debugging difficulties caused by side effects caused by deep comparison. Developers should use appropriate caching methods to ensure the stability of dependent references and avoid unnecessary side effects.

Summary

React chooses a shallow comparison to rely on arrays, which is a balance between performance, design simplicity, and developer controllability. Although shallow comparison brings some challenges, the combination of immutable data design and cache optimization can effectively avoid the indiscriminate triggering of side effects. Understanding this principle can help developers write efficient and robust React function components.
