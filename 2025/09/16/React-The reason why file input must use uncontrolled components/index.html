The reason why file input must use uncontrolled components

Foreword

when building Web applications, file upload is a very common requirement, such as user avatar upload, document submission, image batch processing, etc. In React, we often face a question: why is the file uploaded <input type="file">be sure to use uncontrolled components without using controlled components like a normal input box?

This article will analyze this issue from the perspective of the principle of HTML file input, React’s controlled component model, browser restrictions, etc., and combine code examples with actual development experience to give you a thorough understanding of “Why file input must use uncontrolled components”.

Particularity of file input

the file input element is different from ordinary text input in that it involves data from the local file system rather than pure string information. After the user selects the file, the browser will pass the file data through FileList object is mounted on the DOM element, but this part of the data is read-only , and cannot be directly modified by JavaScript .

From a security perspective, the browser strictly prohibits scripts from setting file paths to prevent malicious programs from accessing or uploading local files without the user’s knowledge.

in React, the core characteristics of the controlled component are: the state of the component is controlled by React, and the value of input is controlled by props or state. . Constraints of Browser Security Mechanism

browser restrictions on file input are based on user privacy and security considerations. JavaScript scripts are not allowed to set the file path, mainly to prevent the following scenarios:

  • the script secretly specifies to upload sensitive files.
  • Users are forced to upload files without knowing
  • third-party script injection attempts to access local system content

therefore, the input[file] valueIt is completely controlled by the browser, and the developer can only passively read it, but cannot actively set it.

Interview Answer: Why can only be uploaded with uncontrolled components?

The controlled component in React essentially controls the state of the component through props, such as the value of input. But <input type="file">, value actually represents the file path selected by the user. This value is read-only for security reasons, and the browser prohibits JavaScript from setting it.

Therefore, React cannot manage this DOM property in a controlled way, otherwise it will throw a warning or the behavior will be invalid. The correct way is to use uncontrolled components, that is, through. ref access the real DOM node, read files list to get the uploaded files.

The summary is: the controlled nature of the controlled component conflicts with the browser’s restrictions on file input and must be handled in an uncontrolled manner instead .

Summary

React is processed. <input type="file">The reason why the controlled component cannot be used is that the browser prohibits the program from setting the file path for user safety. The controlled model of React requires that the input value be controlled through the value attribute, but this is not feasible for file input.

Therefore, in actual development, we must use uncontrolled components with ref to obtain the uploaded file. Understanding the principles behind this can not only avoid code errors, but also enhance the understanding of React design principles and browser behavior mechanisms.

With this knowledge, you can be more leisurely when building Upload modules or form functions, and write code that conforms to the specifications and is robust.
