How do you tell if an attribute comes from the object itself, or from the prototype chain

Foreword

in JavaScript, the properties of an object can be defined directly in the object itself, or inherited through the prototype chain. When we access a property, the engine looks in the object itself, and then looks along the prototype chain. Understanding the “attribution” of properties is important for debugging code, avoiding property overrides, and determining inheritance relationships. This article will make it clear how to distinguish whether a property is defined in the object itself or inherited from its prototype chain.

Review of Attribute Access Mechanisms

when accessing an object’s properties, the JavaScript engine follows the following lookup path:

  1. first check whether the object itself has this property (that is, the object’s own property)
  2. if not, look at the object’s [[Prototype]] which is its prototype object
  3. check again whether the prototype object has the property
  4. if not, continue to look up Object.prototype
  5. if the entire prototype chain does not have this property, return undefined

this search path is the so-called “prototype chain”.

How to determine attribute source

using hasOwnProperty

the most common and authoritative way is to use hasOwnProperty() method to determine whether a property is a property of the object itself.

This method only returns the object “own properties” and does not check the prototype chain.
