Why does react reconciler adopt the fiber architecture

Foreword

React is one of the most popular front-end libraries, and its efficient update mechanism is its core competitiveness. The rereconciler (coordinator) of React is responsible for comparing the old and new Virtual DOM trees, calculating the smallest change set, and applying it to the real DOM.

However, the coordination mechanism before React 16 had performance bottlenecks, especially in the face of complex and large-scale UI updates, which showed the problems of interface lag and slow response.

To overcome these limitations, the React team designed and introduced the Fiber architecture as the underlying implementation framework for the reciller. The Fiber architecture not only optimizes performance, but also lays the foundation for future asynchronous and concurrent rendering. This article will focus on the theme of “Why React Reconsoler Adopts Fiber Architecture” and analyze the design drivers and implementation advantages behind it in detail.

A brief description of the working principle of React reciller

the core responsibility of React reciller is to compare two virtual DOM trees-the old tree and the new tree-to identify the differences, and to generate a set of operations (insert, delete, update), and finally map these operations to the real DOM.

The traditional reciller workflow is synchronous and recursive: Starting at the root node, recursively traversing the subtree, calculating the difference, and finally committing all updates at once. This method is simple and intuitive, but the disadvantages are obvious:

  • blocking main thread : In complex trees or large-scale updates, the rendering task takes a long time, causing the browser to not respond to user input and animation in a timely manner.
  • Lack of disruption capability: Cannot pause or switch during task execution, affecting user experience.
  • Task priority scheduling is not supported the execution order cannot be flexibly adjusted according to the task importance.

Why Does Reconciler Need Fiber Architecture?

1. Solve the main thread blocking problem

the traditional synchronization coordination mechanism will cause a large number of calculations to block the main thread of the browser, especially in the case of a large amount of data and a deep component level, the page stuck phenomenon is obvious.

The Fiber architecture splits the rendering task into tiny units (Fiber units) that are incrementally executed using fragments of browser idle time. This incremental rendering strategy allows the main thread to handle high-priority user interaction events between task executions, significantly improving page responsiveness.

2. Achieve an interruptible coordination process

Fiber supports the suspension, resumption, and restart of task execution by constructing a linked list-like Fiber node structure, avoiding long-term thread occupation and ensuring the flexibility of the coordination process.

This is especially important for mobile terminals and resource-constrained devices, which can effectively reduce interface stuck and user operation delay.

3. Support priority scheduling

different update requests have different priorities in the application, such as user input and animation should take precedence over data loading.

Fiber allows React to dynamically schedule rendering tasks based on updated priorities, improving the responsiveness and user experience of critical tasks.

4. Paving the way for asynchronous and concurrent rendering

Future versions of React introduce a Concurrent Mode, which allows UI rendering to occur asynchronously without blocking the main thread.

The design of the Fiber architecture has good scalability and naturally supports the implementation of concurrent rendering, which is the basis for React to implement this complex function.

How does the Fiber architecture help reciller achieve the above goals?

Core data structure: Fiber node

Fiber is a lightweight linked list node object, each Fiber node corresponds to a node of the Virtual DOM, including node type, state, pointers to child nodes and sibling nodes, etc.

This structure allows React to traverse and split jobs sequentially, facilitating incremental and interrupted implementations.

The rendering process is split into two phases

  • Render (coordination) phase : Create a new Fiber tree and mark the nodes that need to be changed. This phase can be interrupted.
  • The Commit phase : Apply changes to the real DOM, performing side effects. This phase is executed synchronously to ensure that the UI is consistent.

By processing in stages, React avoids long periods of synchronous blocking.

Using Browser Idle Time to Schedule Tasks

React is utilized requestIdleCallbackOr a similar mechanism to execute the Fiber unit of work during the browser’s idle time to ensure that the main thread has enough time to process user events and animations.

question: Why does React reconsoler adopt the Fiber architecture?

Example answer:

the traditional coordination mechanism of React is to synchronously and recursively traverse the Virtual DOM tree. Once the update operation starts, the main thread will be blocked, resulting in interface jam and response delay. To address this bottleneck, React introduced the Fiber architecture.

Fiber breaks down the rendering task into a finer-grained unit of work, uses a linked list structure to represent node relationships, supports incremental execution and interruption of tasks, and avoids blocking the main thread for a long time. At the same time, Fiber allows to schedule the execution order according to the task priority, improving the response speed of high-priority tasks. More importantly, the Fiber architecture lays the foundation for asynchronous and concurrent rendering, meeting the high performance and user experience requirements of modern complex interactive applications.

Summary

React reconsoler uses the Fiber architecture to address the performance and user experience deficiencies of traditional synchronization and coordination mechanisms. Fiber significantly improves the rendering efficiency and response speed of React through task splitting, interruptible execution, priority scheduling, and phased rendering.

This architecture not only optimizes current rendering performance, but also provides a solid foundation for future asynchronous concurrent rendering modes, enabling React to better cope with complex and dynamic modern Web applications. Understanding the original design and implementation of Fiber helps to deeply understand the internal update mechanism of React, and provides theoretical support for performance optimization and high-level function development.
