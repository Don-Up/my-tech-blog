Why don’t uncontrolled components use onChange

Foreword

in React, the state management of form components is usually divided into two modes: Controlled Components and uncontrolled components. The controlled components pass through React’s state to manage input values, data flow is unidirectional and easy to debug, while uncontrolled components rely directly on the state of the DOM element itself, using ref to access the input.

One notable difference is that the controlled components typically bind onChange event to synchronize input content with React state, while uncontrolled components are rarely used or not recommended onChange . This article will focus on “why not use non-controlled components.” onChange 」 This problem, in-depth analysis of the principles and design considerations.

Working Mechanism of Uncontrolled Components

the uncontrolled component does not rely on the state of React to control the input content, but directly uses the browser DOM node to save the input value. Developers through ref get the input element and read the current value when needed (such as submitting a form).

The role of onChange and its relationship to controlled components

onChangeEvents are used to capture changes in input content and are a key bridge between synchronized state and UI in controlled components. When the user enters, onChange this triggers an update to the React state, which drives the re-rendering of the input box content.

Controlled components require frequent calls onChange to keep the React state consistent with the DOM display, forming a controlled state.

Why not use onChange for non-controlled components

uncontrolled components not used onChange mainly for the following reasons:

  1. no need to synchronize status in real time

uncontrolled components do not rely on React state control input values, onChange triggered frequent status updates are meaningless. It is simpler and more efficient to read the value of the DOM node directly.

  1. Avoid Useless Rendering

if an uncontrolled component is bound to onChange and call in the event setState , will cause the React component to re-render frequently, losing the advantage of non-controlled components to avoid frequent rendering.

  1. Reduce performance overhead

in large forms or frequent input scenarios, uncontrolled components eliminate the overhead of state synchronization and are suitable for scenarios with high performance requirements.

  1. Code is concise and closer to native DOM operations

uncontrolled components are more like traditional HTML forms, using ref read the value directly, the code logic is simpler, and no additional state needs to be maintained.

Common usage scenarios for uncontrolled components

  • file Upload Component : The file type cannot be controlled and needs to be passed. ref gets the list of files.
  • Third-party UI library integration : Some Library components have their own state, and the use of uncontrolled can reduce conflicts.
  • Quick Form Collection : For scenarios that do not require real-time verification or linkage, just read the input when submitting.
  • Performance-sensitive scenarios avoid frequent state updates and rendering overhead.

Uncontrolled components do not use onChange because it does not need to synchronize the input value through The React state, onChange events are primarily used for controlled components to keep state synchronized with inputs.

Binding onChange and call setState this will cause the component to render frequently, losing the advantages of the uncontrolled component to avoid frequent rendering and improve performance.

Non-controlled components directly throughref access DOM element values, which is suitable for scenarios that do not require real-time monitoring of input changes, performance-sensitive, or third-party integration.

Summary

the design idea of the uncontrolled component is to let the browser DOM element itself manage the input state, React only when needed. ref access data. Since no synchronization state is required, the binding onChange it loses its relevance and may instead impose a performance burden.

Reasonable selection of controlled and uncontrolled components can balance code complexity and performance according to requirements, ensuring functional integrity and improving user experience. Understanding Uncontrolled Components onChange the reason is to help developers write more efficient and concise React form code.
