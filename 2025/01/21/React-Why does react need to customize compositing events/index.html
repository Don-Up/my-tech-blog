Why does react need to customize compositing events

Foreword

in modern Web development, event handling is the core mechanism of user interaction. Although browser native events are rich in functions, there are problems such as browser compatibility differences, high performance overhead, and complex event processing. React introduces a synthetic event system to uniformly encapsulate and manage native events based on the event delegation mechanism, greatly simplifying the event processing logic.

However, why does React not use browser native events directly, but choose a custom synthetic event system instead? This article provides an in-depth analysis of the design intent, implementation principles, and advantages of React custom composite events to help you better understand the need for this core mechanism.

Deficiencies in browser native events

the native event model of the browser is the DOM Level 2 standard, which basically meets the requirements, but there are many limitations and defects in actual development.

1. Cross-browser compatibility issues

different browsers have different implementations of event types, Event object properties, and event bubbling/capturing behavior. For example, there is a big difference in the event model between IE and modern browsers, resulting in front-end code that must be compatible with multiple versions of browsers.

2. Performance issues

binding an event listener to each DOM element incurs memory and performance overhead. In large single-page applications, binding a large number of event listeners will cause large browser memory pressure and reduced event triggering efficiency.

3. Event objects are not uniform

the property names and structures of native event objects are not exactly the same in different browsers, and developers need additional encapsulation processing, which increases code complexity.

4. Event management is difficult

When events occur, it is difficult to uniformly schedule event callbacks, implement priority control, and batch updates, especially in complex component trees.

React Design goals for custom synthetic events

based on the above problems, React customizes the synthetic event:

  • unified Event Interface , which masks browser differences and provides consistent event objects and methods.
  • Event delegation mechanism , only bind event listeners to the root node to reduce the number of listeners and improve performance.
  • Event pool mechanism , reuse event objects, reduce memory pressure (before React 16).
  • Event Scheduling Integration to facilitate React to control the update priority when the event is triggered, and realize batch update and scheduling.
  • Extensibility to facilitate React to extend and enhance event behavior.

Principle of React Synthetic Event

React registers a few native event listeners on the application root node, such click , keydown and so on, using event bubbling to capture all child node events.

When the event is triggered, React:

  1. capture native events, create synthetic event objects SyntheticEvent, which encapsulates all the properties and methods of the native event, and unifies the interface.
  2. Find the React Fiber node based on the DOM node that triggered the event and determine the event handler function.
  3. The corresponding event callback is executed in turn, during which event propagation and default behavior can be controlled.
  4. React also uses synthetic events to integrate event scheduling mechanisms to achieve updated priority management and Batch Rendering.

In addition, before React 16, synthetic event objects will be reused to reduce the pressure of garbage collection. React 17 cancels the event pool and uses ordinary event objects instead to solve potential problems in asynchronous events.

Benefits of Custom Synthetic Events

aspects description
cross-browser compatible encapsulates the differences between different browser events and provides a unified interface and behavior.
Performance optimization event delegates reduce the number of listeners, and event pools reduce memory overhead.
Unified Management centralized event management facilitates event scheduling, batch processing, and priority control
scalability easily add custom behaviors at the synthetic event level, such as blocking bubbles and enhancing event composition
simplify the development experience unified event interface reduces compatibility processing and improves development efficiency

Interview Answer: Why does React need to customize synthetic events?

React selects custom synthetic events to unify event differences across browsers, reduce the number of event listeners, and improve performance and development experience.

Through the event delegation mechanism, React binds only a few event listeners to the root container, avoiding the performance and memory consumption caused by binding events to each node. At the same time, synthetic events encapsulate Native event objects, shield browser compatibility differences, and provide a unified interface.

Composite events also facilitate React to implement event scheduling and batch update control, improving rendering efficiency. In summary, custom synthetic events are an important design decision for React to build a high-performance, cross-platform UI framework.

Summary

React custom synthetic event system is an innovative solution designed based on the inadequacy of the browser Native event model. It combines mechanisms such as event delegation, Event object encapsulation, event pooling, and scheduling integration to optimize performance and improve the flexibility of the development experience and framework.

Understanding this mechanism will help developers accurately grasp the operating principles of The React event system, better write efficient and robust event handling code, and lay a solid foundation for in-depth study of The React internal architecture.
