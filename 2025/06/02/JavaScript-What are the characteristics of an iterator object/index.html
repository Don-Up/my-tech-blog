Basic characteristics of iterator

an Iterator is an interface mechanism that provides uniform access to various data structures. As long as an object implements Symbol.iterator method and returns a next() method, we call it an “iterable object”.

The Iterator object is essentially a objects with specific interface conventions the core features are as follows:

1. Must have next() method

each call to this method will return a result object {value, done} :

  • value the value returned by the current iteration.
  • done : A Boolean value that indicates whether the iteration has completed.

2. Each iterator is state-persistent.

The iterator remembers the current traversal position, unlike the traditional for loop that starts from the beginning each time, the iterator is. One-time consumption it cannot be reset.

3. Can be adopted for...of traversal

as long as the object implements Symbol.iterator method, it can be for...of ES6 syntax support, extension operators, and destructured assignment.

4. It is “inert evaluation”.

Even an infinite sequence (such as a Fibonacci sequence) can be expressed by an iterator because it only calls each time. next() when generating values.

Relationships with built-in iterable objects

many of the built-in structures in JavaScript have the iterator interface built in:

  • array [Symbol.iterator] returns an ArrayIterator object
  • Map and Set also have their own built-in iterators.
  • String, TypedArray, and DOM NodeList also support iteration

the behavior of these iterators is automatically defined, and we can call obj[Symbol.iterator]() gets their iterator object.

Relationship with generators

A generator is actually a higher-level syntactic sugar form of creating an iterator. Any generator function (using function* definition) returns an object that conforms to the iterator protocol.

In this example iter is a standard iterator object with all the behavior.
