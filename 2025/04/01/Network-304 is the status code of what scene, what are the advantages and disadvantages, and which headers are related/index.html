304 is the status code of what scene, what are the advantages and disadvantages, and which headers are related

Foreword

In modern Web applications, optimizing front-end performance and reducing server pressure are frequent concerns for developers. As one of the most basic and effective means of optimization, browser cache plays a vital role. In the HTTP protocol 304 Not Modified the status code is designed to implement intelligent cache control. Many front-end or back-end engineers have heard of 304, but they may not have a deep understanding of its principles, usage scenarios, Header involved, and its impact.

This article will focus on the 304 status code, analyze its typical usage scenarios, dependent headers, the advantages and disadvantages of performance, and explain it with actual code examples.

Definition and Usage Scenarios of 304 Status Code

HTTP status code 304 Not Modified indicates that the resource has not changed since the last request, and the client can use the locally cached version directly without having to download it again. This status code does not contain the response body, only the response header information.

304 status codes typically appear in the following scenarios:

  1. when a browser accesses a page or resource, if the resource has been previously cached, it automatically carries a conditional request header (e. G. If-Modified-Since or If-None-Match ) Confirm with the server whether the resource is updated.
  2. The server returns the 304 status code after determining that the resource is not updated.
  3. The browser reuses the local cache to improve response speed and reduce traffic and bandwidth consumption.

This process is called negotiate cache (Conditional Request) , and Cache-Control, Expires different.

Request and response headers associated with 304

request header (initiated by the browser)

Header field meaning
If-Modified-Since returns a complete response if the resource has been modified since a point in time
If-None-Match if the ETag value of the resource does not match, a complete response is returned.

Response header (returned by the server)

Header field meaning
Last-Modified indicates the last modification time of the resource
ETag unique identifier (hash, version, etc.)
Cache-Control control the cache policy (for example, no-cache means negotiation verification is required)
Expires Indicates the absolute time at which the resource expires (replaced by Cache-Control)

when the browser initiates a request, it is based on the last cached ETag or Last-Modified join If-None-Match or If-Modified-Since and the server checks and decides to return 200 or 304.

Benefits of 304

save bandwidth : No need to transmit duplicate content, only return Header information, significantly reducing the resource size. Improve performance : The client directly uses the local cache to load pages faster, especially static resources such as images, scripts, and styles. Reduce server stress : The server avoids repeated processing and transmission when the content remains unchanged.

Potential Disadvantages of 304

the validation request still requires a round trip : Although the resource has not changed, the negotiation cache still requires a complete request-response process (Header level), which still has a certain delay compared with the strong cache (direct hit local).

Failure judgment may be inaccurate :

  • Last-Modified the accuracy is seconds, and some frequently changing resources may be misjudged as unchanged.
  • ETag if the generation is inconsistent (such as deployment differences), even if the content is consistent, it may be misjudged as updated.

Sometimes it does more harm than good to performance :

in some high-frequency access systems, the number of requests is large, and even if the 304 response is small, the service pressure may be concentrated on the “negotiation judgment.

Interview answer

interviewer Questions what is the use of 304 status codes? What are its advantages and disadvantages? What headers are involved?

Answer:

304 is a status code in the HTTP protocol, indicating that the resource has not changed and the client can directly use the local cache copy. The main application is in the negotiation caching mechanism, that is, the browser carries through the request header. If-Modified-Since or If-None-MatchThe server returns 304 (unchanged) or 200 (Updated) depending on the resource status.

The advantage is to save traffic, speed up the loading speed, reduce the burden on the server, the disadvantage is that still need to initiate request verification, there is still pressure for high concurrent services, and the judgment mechanism is not always accurate.

The request headers involved in the 304 status code include If-Modified-Since and If-None-Match and the response header includes Last-Modified , ETag , Cache-Control and Expires .

Summary

304 status code is an important part of the HTTP cache mechanism, which avoids repeated transmission through resource verification and effectively improves Web performance. In the actual development, we should combine the strong cache and the negotiation cache strategy, and set the response header reasonably according to the characteristics of the resource, so as to maximize the performance optimization value.

Understanding the essence of 304 is to understand the caching mechanism of HTTP, which is one of the foundations for building high-performance Web services. When designing a resource request strategy, it is necessary to consider not only the cache hit efficiency, but also the server load and content accuracy.
