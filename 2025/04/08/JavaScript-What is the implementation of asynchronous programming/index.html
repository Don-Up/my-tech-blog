What is the implementation of asynchronous programming

Foreword

JavaScript is a single-threaded language and naturally cannot perform multiple tasks at the same time. However, a large number of operations in front-end development are asynchronous, such as network requests, timers, DOM Event responses, etc. To avoid blocking the main thread and improve the user experience, JavaScript provides a variety of asynchronous programming implementations. Understanding the principles and usage scenarios of these methods is a basic skill for front-end developers.

Mainstream Implementation of Asynchronous Programming

Callback Function (Callback)

the earliest asynchronous way was to use a callback function. Manually calling the incoming callback after the function is executed is simple and straightforward, but as the nesting level increases, callback hell is prone to occur.

The disadvantage is that callbacks are too deeply nested, difficult to maintain, and exception handling is scattered.

Event listening (EventEmitter / DOM Events)

event-triggered mechanisms handle asynchrony, such as button clicks, file read completion, timer timeout, etc. The event model is an implementation of the observer pattern and is suitable for asynchronous but not strongly state dependent scenarios.

Although flexible, it is not suitable for asynchronous operations that are strongly dependent on the order of execution.

Promise(ES6)

Promise is an asynchronous abstraction designed to solve the problem of callback nesting, and the core is the encapsulation of asynchronous state. It has pending , fulfilled ,rejected three states, and through then and catch method is called in a chain.

Promises improve readability and maintainability, but still have some limitations when dealing with complex asynchronous processes (such as sequential + concurrent + branching).

Generator + co

the Generator function can interrupt execution. When an asynchronous operation is used, the asynchronous process can be suspended and the execution result can be waited for before continuing. However, the Generator itself is not asynchronous and needs to be iterated automatically with a third-party library (such as co).

The writing method is close to synchronization logic and is a transition scheme for async/await.

async/await(ES8)

async/await is syntactic sugar built on promises that makes asynchronous code look like a synchronous process. As long as the function is preceded async , can be used internally await to “pause” the asynchronous operation until the result is returned.

It greatly improves readability and maintainability, and is currently the most recommend asynchronous method.

Timer (setTimeout / setInterval)

Although not specifically designed for asynchronous control flow, timers are one of the most basic asynchronous mechanisms in JavaScript and essentially rely on the browser’s task queue scheduling.

Commonly used in timing scenarios such as throttling and polling.

Interview answer

there are several ways of asynchronous programming in JavaScript: callback function, event listening, Promise, Generator with co, and async/await.

The most basic is the callback function, but it is easy to fall into callback hell. Later, there was an event listening mechanism, such as the DOM Event of the browser or the EventEmitter of Node.js, but this is more of an event-driven model and is not suitable for handling asynchronous processes that require a clear execution order.

ES6 introduced promises, which changed the asynchronous writing method, made the code clearer and easier to maintain, and supported chain calls and unified error handling. Later, the community tried to use the Generator function with the co library to further improve the readability of asynchronous logic, but the writing method was more complicated.

What really makes asynchronous programming as intuitive as synchronous is async/await. It is a Promise-based package. You only need to add an async function and await to write asynchronous logic in a synchronous manner. Exception handling can also be written directly with try/catch.

In addition to these, there are timers and asynchronous operations in the Web API, such as fetch, setTimeout, MessageChannel, and so on.

I will choose the most suitable asynchronous scheme according to actual business needs, such as Promise for simple logic and async/await for complex logic. If concurrency control is involved, it is also used in conjunction with helper methods such as Promise.all and Promise.race.

Summary

asynchronous programming is critical in JavaScript, and everything from callbacks to async/await is constantly optimizing the readability and maintainability of your code. Understanding their core principles and applicable scenarios will not only help to write higher-quality code, but also demonstrate a solid technical foundation in the interview. At present, async/await has become the mainstream, and it is recommended to master and use this scheme first.
