How to do Promise cache

Original Title: How to do Promise cache? The Promise of the last function call is not returned, then the next function call still returns the previous Promise.

Foreword

in front-end development, some asynchronous operations, such as interface requests or data calculations, may be called frequently. To avoid repeating the same asynchronous task and improve performance and resource utilization, a Promise Cache mechanism is commonly used to reuse existing Promise instances. This article will explain in detail the implementation of the Promise cache ideas, typical scenarios and considerations to help you understand and apply this technology.

The core idea of Promise cache

the goal of the Promise cache is to allow subsequent calls to the function to return the same Promise when the asynchronous operation is not completed, rather than repeatedly initiating new asynchronous requests. In this way, repeated execution of the same request is avoided, and efficiency is improved.

The core approach is:

  1. save a variable outside the function or in a closure that stores the Promise currently in progress.
  2. When the function is called, check whether the cache variable exists and is still valid (not resolved or rejected).
  3. If it exists, return the Promise directly.
  4. If it does not exist, the asynchronous operation is performed, the new Promise is generated and cached, and finally it is returned.
  5. After the Promise status changes, you can choose to clear the cache and allow the next call to be re-executed.

Applicable scenarios for caching

  1. interface anti-shake
    avoid repeated requests when the user clicks the request button multiple times in a short period of time.
  2. Data sharing
    multiple components request the same data at the same time to avoid repeated pulling.
  3. Compute Task Cache
    when complex computation functions are executed asynchronously, cache promises to avoid repeated computations.

Precautions

  • once the cache Promise is cleared, the next call will reinitiate the request, and the cache duration should be selected according to the business needs.
  • If the asynchronous task fails (reject), you should also empty the cache to avoid returning an error Promise all the time.
  • Caching is suitable for asynchronous operations with no side effects and stable results, avoiding data synchronization problems caused by caching.

Interview answer

the key to implementing the Promise cache is to maintain a variable outside the function to store the current Promise. When the function is called, judge whether the cache exists. If it exists and the asynchronous task has not been completed, return the Promise directly to avoid repeated asynchronous operations.

I would use .finally() the method clears the cache after the Promise completes (whether it succeeds or fails), ensuring that the cache is not permanently occupied and that it can be retried after failure.

This design is very suitable for scenarios where the interface is anti-shake and data is shared, such as multiple components requesting the same interface, or preventing users from repeatedly clicking to initiate repeated requests.

However, it should be noted that the cached Promise must be an asynchronous task with no side effects and stable results to avoid inconsistent data caused by caching.

If the asynchronous task fails, the cache also needs to be cleaned up in case subsequent calls return the failed old Promise.

The overall implementation is relatively simple, but can significantly improve performance and user experience.

Summary

Promise caching is an efficient way to reuse the results of asynchronous tasks. It avoids duplicate requests and calculations by caching the currently executing promises. Reasonable design of cache timing and cleanup logic can make asynchronous operations more efficient and stable. In actual projects, Promise cache is often used in scenarios such as interface anti-shake and multi-component sharing data, and is a practical technique for front-end performance optimization.
