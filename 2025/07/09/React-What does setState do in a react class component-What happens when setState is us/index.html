What does setState do in a react class component-What happens when setState is us

Foreword

in React’s class component, setState is the core API for updating component status. Although we are used to using it in function components. useState and other Hooks, but class components are still used in a large number of historical projects and in some specific scenarios. Therefore, in-depth understanding of class components. setState it is important for development, debugging and performance optimization.

This article will explain the system setState the internal working mechanism, starting from the call, talks about the update queue, batch processing, scheduling rendering, life cycle call and other details, to help you build the overall understanding of the React status update process.

A review of the basic usage of setState

when we click the button, setState is called, seemingly simply modifying state , but there is actually a complex scheduling and optimization process behind it.

What did setState do?

First, add the Update to the Queue (Update Queue)

the status Update in React is not executed immediately, but is put into an Update Queue:

At this time, React will not be modified immediately. this.state instead, the update object is wrapped into a Update instance to the corresponding Fiber node of the current component updateQueue in.

Second, judge whether it is a batch scenario.

React determines whether the current update is in a batch environment (e. G. Event handler, lifecycle, synthetic event). If so, React delays execution; Otherwise, an update is triggered in the microtask.

For example:

in the synthetic event, the two updates are merged and updated together in one render.

Three, mark the component as dirty, trigger scheduling.

When the update is queued, React marks the current component need to update and add it to the scheduler. The scheduler starts a rendering process when the browser is idle or when appropriate.

In the Fiber architecture, this phase is called Schedule (Schedule) its core goal is to find out which components need to be updated and build the update task.

Four, enter the update process of Fiber (recocation)

the scheduler starts processing these components marked as updated, enteringreconciliation phase. This process includes:

  • traversing the Virtual DOM tree
  • contrast old and new Fiber tree (Diff)
  • create a new Fiber node
  • prepare to generate updated DOM description

at this stage, React does not directly manipulate DOM, but builds a new Fiber tree.

Five, enter the commit phase, update DOM and life cycle

at the end of the coordination phase, React enters the commit phase this phase is divided into three sub-phases:

  • beforeMutation : such getSnapshotBeforeUpdate
  • mutation : perform DOM updates (such appendChild , setTextContent etc.)
  • layout : such as calling componentDidUpdate , componentDidMount

This is when the page really changes.

Several Writing Methods and Differences of setState

writing Method 1: object form

disadvantages: this.state it is updated asynchronously. If it depends on the previous value, an error may occur.

Writing Method 2: functional form (recommend)

pros: Ensure you get the latest state suitable for use in continuous updates.

Writing method 3: With callback function

for scenarios where you want to execute some logic immediately after a state update.

Batch mechanism

react. setState in a certain environment. Asynchronous , which refers to “state updates and component re-rendering are done asynchronously”, not to setTimeout asynchronously.

Default Batch Environment

  • React synthetic event
  • life cycle function
  • ReactDOM.unstable_batchedUpdates

non-Batch Environment (status takes effect immediately)

  • setTimeout ,setInterval , Native Events
  • Promise.then

but starting with React 18, use createRoot when, batch processing is automatically enabled for all scenarios , even in promises, setTimeout.

interview answer: What did setState In React class component do?

Class component call in React setState will trigger a series of processes. First, it puts the status update into the update queue and marks the current component as “pending update”. React determines whether batch processing is possible and schedules update tasks in the scheduler. After that, we enter the coordination stage, compare the old and new Virtual DOM by building a new Fiber tree, and find out the changed parts. Finally, it enters the commit phase, actually updates the DOM, and calls the lifecycle method.

In addition, setState it is asynchronous in nature and merges multiple updates for performance optimization. It is recommended to use functional in scenarios that depend on the previous state. setState make sure the logic is correct.

Summary

in The React class componentsetState although it looks like a simple state modification method, it hides a complex scheduling and update mechanism behind it. It not only updates the component state, but also pulls out the complete flow of Fiber scheduling, batch optimization, update queue management, Virtual DOM Diff, DOM update, and lifecycle hooks.

Understanding these principles is critical to optimizing component performance, avoiding unnecessary re-rendering, and properly organizing state update logic. Although modern development prefers to use function components and Hooks, master class components. setState the principle is still the skill reserve that senior React engineers should have.
