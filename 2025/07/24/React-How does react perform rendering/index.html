How does react perform rendering

Foreword

React is a JavaScript library for building user interfaces. Its core idea is to achieve efficient and predictable UI construction through componentization and state-driven methods. In the process of using React, developers often only focus on component writing and state management, but rarely understand how React completes the whole process from component code to page rendering.

In fact, React’s rendering mechanism has undergone many evolutions, from the initial synchronous recursive rendering to the later Fiber architecture, which supports Task interruption, priority scheduling, and concurrent rendering. The design ideas and implementation details behind it are very worthy of in-depth study. This article will systematically explain the rendering mechanism of React, including the first rendering, update rendering, Fiber architecture, Virtual DOM, diff algorithm, commit phase and other key contents.

Overview of the overall process of React rendering

the rendering process of React is mainly divided into two stages:

Render phase : Build a new virtual UI structure, compare the differences between the old and new trees, and generate an update plan. This phase can be interrupted.

The Commit phase applies changes to the real DOM and triggers a lifecycle or side effect callback. This phase is synchronous and uninterruptible.

These two phases are called “Reconciliation” and “Commit”.

when callingroot.render ( <App />) React performs the following steps:

  1. will <App />convert to the corresponding React element object
  2. build a Fiber tree (virtual structure) based on the object
  3. process function calls, Hooks execution, etc. of each component in turn
  4. construct an effect list that describes the contents of the update (such as creating a DOM node)
  5. in the commit phase, traverse the effect list and insert the corresponding DOM node into the page.

During the first rendering, there is no diff operation, and React builds the entire tree from scratch.

update rendering: how state changes trigger re-rendering

when the internal state of the component changes (e. G. setCount(count + 1) ) or props changes, React triggers a component update. The overall process is as follows:

  1. React marks the component as “needs to be updated”
  2. re-enter the render phase and generate a new virtual tree
  3. compare with the old tree to find changes (by diff algorithm)
  4. generate the update operations that need to be performed (insert, delete, update attributes, etc.)
  5. Enter the commit phase, actually operate DOM, and call side effects

this process embodies React’s “declarative programming” philosophy: developers describe the UI state, and React automatically handles the update logic.

Fiber Architecture: Supports Interruptible Rendering

React 16 introduces the Fiber architecture to replace the previous synchronous recursive update model. A Fiber is a linked-list representation of a component tree that allows tasks to be broken, resumed, and sliced during rendering.

the render phase of Fiber uses depth-first traversal, building child nodes first, and then sibling nodes. Because of its linked list structure, React can interrupt traversal at any time and return control to the browser for user interaction.

diff algorithm: find the minimum cost of change

when the state or props changes, React rebuilds a new Fiber tree and compares it to the old tree. This comparison process is the diff algorithm, and the goal is to find the minimum amount of change.

React’s diff algorithm has the following optimization strategies:

  1. same-layer comparison: only compares nodes at the same level to avoid cross-layer overhead.
  2. If the type is the same, reuse: only attribute differences are compared for nodes of the same type, and the original DOM is retained.
  3. Use key to optimize list rendering: help quickly locate additions, deletions and changes to improve performance

commit phase: change application and side effect execution

in the commit phase, React traverses the effect list generated in the render phase and performs the DOM operations marked in each effect:

  1. for nodes that need to be inserted, call appendChild
  2. for nodes that update attributes, call the DOM API to update attributes
  3. for the node that needs to be deleted, call removeChild

it will also be implemented at this stage:

  • lifecycle methods (such componentDidMount )
  • side effects (such as Hook useEffect )
  • update of Ref

since This phase involves real DOM changes, it is synchronous and uninterruptible.

React rendering performance optimization means

React provides several ways to optimize rendering performance:

memoization mechanism : Use React.memo, useMemo , useCallback cache components or functions to avoid repeated calculations or re-rendering

shouldComponentUpdate / PureComponent : Manual or automatic shallow comparison in class components to avoid invalid updates

the correct use of key : Helps React compare nodes more efficiently and avoid unnecessary rebuilds.

Inert loading : Use React.lazy and Suspense reduce first-time load costs by enabling on-demand loading of components

interview answer: how does React render?

Answer:

the rendering process of React is divided into two stages:

  1. Render phase : When the component state or props changes, React will build a new Fiber tree and compare it with the old tree to generate a series of update operations. This phase is asynchronous and can be interrupted.
  2. The Commit phase : Apply the update to the real DOM and perform side effects (such as lifecycle functions or useEffect). This phase is synchronized.

React uses the Fiber architecture to implement interruptible rendering and task scheduling, improving performance and responsiveness. At the same time, Virtual DOM and diff algorithms are used to optimize the minimum update path to ensure that only the necessary parts are updated.

The whole process embodies the core concepts of React: declarative, responsive, and high-performance.

Summary

react’s rendering mechanism is fundamental to its performance and responsiveness. It implements a controllable and interruptible update process through the Fiber architecture, and splits the rendering process into two stages: render and commit, thus ensuring high-performance rendering of complex UI.

Understanding the rendering process of React not only helps to write correct code, but also helps to make more reasonable performance optimization, state management strategies, and component design choices in actual development. It has very important guiding significance for in-depth study of React, preparation for high-level interviews, and solving performance bottlenecks.
