Can the Promise be canceled

Foreword

in front-end development, we often use promises to handle asynchronous tasks, such as initiating network requests, reading files, etc. But there is an obvious pain point: once the Promise starts executing, it cannot be interrupted. In contrast, like XMLHttpRequest.abort() or some event listeners can be canceled. So, can the Promise be canceled? If not, how do we implement a “pseudo-cancellation” mechanism? This article will focus on the analysis of this problem.

Why can’t the Promise itself be canceled?

Promises are designed to “represent a value that, once created, will complete or fail in the future”. It emphasizes certainty and immutability: Once a state is changed, it cannot be modified.

This means that if you make a Promise, it will either resolve or reject it, whether or not you still need the result.

Even if you no longer need the result, the Promise will continue to execute the internal logic.

How to implement a cancelable asynchronous task?

Although the Promise itself cannot be canceled, we can use other mechanisms to implement “ pseudo-cancellation “. There are two most common methods: flag bit control and using AbortController.

Method 1: Manually control whether to process the result through the flag bit

this way is to expose a cancel()Method, which essentially does not stop the timer, just ignores the result processing.

Method 2: Use AbortController with Fetch to realize real cancellation

of modern browsers. fetch interface support and AbortController combined use:

this method can really interrupt the underlying request and is currently the recommend way to handle asynchronous cancellation.

Third-party library support cancellation

some third-party libraries (such as Axios) also provide the cancellation function. The old version of Axios uses CancelToken, and the new version supports native AbortController, which is used in a similar way.

The future of the cancellation of the Promise may

the TC39 proposal was proposed. Cancelable Promise , but has been withdrawn due to a large conflict with existing semantics. At present, there is no official plan to cancel the built-in function.

Interview answer

the Promise itself cannot be canceled. It is designed to complete or fail once it is started, and once the state is determined, it is irreversible. This is determined by the nature of the Promise.

However, in actual development, we do often need to “interrupt” some asynchronous operations, such as canceling network requests or preventing users from clicking and repeating processing. Although we can’t really cancel the Promise itself, we can do it indirectly through some mechanisms:

One way is to use flag bit control to determine whether the result needs to be processed only after the Promise is executed. This method does not prevent internal operations, such as setTimeout will continue to execute, but we ignore the processing after resolve.

Another more elegant way is to use AbortController, which is matched with fetch or a library that supports this signal, and can really stop network requests. This is the current standard Asynchronous cancellation scheme on the front end.

Therefore, in summary, the Promise itself does not support cancellation, but the cancellation control of asynchronous tasks can be realized through the flag bit, AbortController or third-party library.

Summary

the non-cancelability of promises is a major limitation, but we have a variety of means to circumvent this problem in actual development. By understanding the design philosophy of Promise and combining the use of AbortController, flag bit or adaptation library, we can still flexibly control the execution and interruption of asynchronous tasks, bringing better interaction experience for users.
