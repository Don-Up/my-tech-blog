What is the working principle of the fiber architecture

Foreword

React introduced a new scheduling mechanism and architecture since version 16, called the Fiber architecture. Fiber is the underlying mechanism that React uses to coordinate and schedule tasks, completely changing the way React handles updates. Its goal is to solve the performance bottleneck in the previous React rendering process, especially for large-scale updates and complex interaction scenarios, to ensure a smoother user interface response speed and interactive experience.

This article describes in detail the original design intention, core data structure, workflow, and advantages of the Fiber architecture over the old architecture to help readers understand how React implements efficient rendering scheduling through Fiber.

The Background and Design Goal of Fiber Architecture

before React 16, the rendering update of React is performed synchronously, that is, once the rendering process is started, the entire update task will be completed at one time. Although this is simple, it is easy to block the main thread when processing a large number of nodes or complex UI, resulting in page jamming and unsmooth interaction.

The design objectives of the Fiber architecture include:

  1. interruptible Rendering Work : Support splitting the rendering task into smaller units and executing it step by step to ensure that the main thread can handle high-priority tasks (such as user input) and avoid long-term blocking.
  2. Incremental rendering : allows React to render updates in batches over multiple frames to share the computational load.
  3. Priority Scheduling : Dynamically adjust the rendering order according to task priority to ensure that key tasks are executed first.
  4. More flexible update control: such as error boundary handling, concurrent rendering, etc.

Fiber core data structure

Fiber is essentially a linked list structure, each Fiber object corresponds to a node in the React Virtual DOM tree, which contains the current node status, attributes, child node relationships and other key information.

The following is a schematic (simplified version) of the core fields of the Fiber structure:

field Name role description
type node type, such as component type, HTML tag type, and so on
key used to uniquely identify nodes and assist React in identifying node changes.
stateNode the real DOM node or component instance associated with the current Fiber
return point to parent Fiber node
child pointing to the first child Fiber node
sibling point to the next sibling Fiber node
pendingProps props passed in during this update
memoizedProps last render cached props
memoizedState Last render cached state
effectTag mark the side effects that the node needs to execute this time.
nextEffect point to the next node in the linked list that needs to perform side effects

the Fiber structure allows React to traverse the entire virtual DOM tree in the form of a linked list, while preserving the state comparison of the old tree and the new tree, thus efficiently managing updates.

Workflow of Fiber

the rendering process of Fiber is mainly divided into two stages: Render phase (coordination phase) and Commit phase .

1. Render phase (coordination phase)

  • this phase is the process of building a new Fiber tree, calculating which nodes need to be updated, deleted, or added.
  • This phase can be interrupted and resumed. React will split the task into multiple small units (unit of work), and execute a small part at a time. After the execution is completed, you can pause and wait for the main thread to continue when it is free.
  • Through the priority mechanism, React processes high-priority update tasks first to ensure smooth user interaction.
  • This phase does not trigger any side effects and is only responsible for preparing the update operation.

2. Commit phase

  • This phase applies the update operation prepared in the Render phase to the real DOM.
  • Once the Commit phase is entered, execution is synchronous and uninterruptible, ensuring UI consistency.
  • This includes performing DOM updates, calling Lifecycle methods (such as componentDidMount, componentDidUpdate), and triggering side effects.

Advantages of Fiber over the old architecture

the old version of React executes the entire update tree synchronously when updating, resulting in blocking the main thread once the rendering task starts, which is a poor experience. Fiber brings the following improvements:

  • task can be interrupted , Improve the response speed and avoid long-term jamming
  • support task priority scheduling , allocate CPU time more reasonably
  • incremental updates and time slicing , the update is completed in multiple frames.
  • More flexible error handling , such as the error boundary
  • Laying the Foundation for Concurrency Patterns support for future asynchronous rendering and Suspense

interview answer example

question: Please briefly describe the working principle of the React Fiber Architecture and its original design intention.

Example answer:

React Fiber is a new coordination and scheduling architecture introduced by React 16, which aims to solve the performance bottleneck in the traditional React rendering process. Traditional React executes the entire virtual DOM tree synchronously when updating, which easily blocks the main thread and affects the page response.

Fiber enables incremental execution and interruptible scheduling of tasks by splitting the rendering task into smaller units (Fiber units). Fiber uses a linked list structure to represent Virtual DOM nodes, supports priority scheduling, and can dynamically adjust the execution order according to the importance of tasks, thus ensuring that high-priority tasks (such as user input) can be processed in a timely manner.

Its workflow is divided into Render phase and Commit phase. The Render phase is responsible for building a new Fiber tree and can interrupt recovery. The Commit phase is responsible for synchronous Commit updates to the real DOM. The Fiber architecture improves the performance and user experience of React and lays the foundation for future concurrent rendering.

Summary

Fiber Architecture is a core technology designed by React to improve rendering performance and user experience. By splitting rendering tasks, incremental execution, and priority scheduling, Fiber enables React to better respond to user interactions and avoid interface jarring. Its two-stage process (Render and Commit) clarifies the Working Boundary and improves the controllability and scalability of rendering.

Understanding the Fiber architecture helps you gain insight into the internal update mechanism of React, optimize application performance, and lay a solid foundation for mastering advanced features such as the concurrent mode and suspend of React.
