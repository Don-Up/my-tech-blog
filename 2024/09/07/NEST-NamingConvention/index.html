Nest.js Project Structure and Naming Conventions

2024-09-07
#Nest.js
Nest.js

Nest.js is a progressive Node.js framework for building efficient, scalable, and maintainable server-side applications. A well-organized project structure and consistent naming conventions play a crucial role in maintaining readability and scalability. In this blog, we will explore the recommended Nest.js project structure and best practices for naming conventions.

Recommended Project Structure

A typical Nest.js project follows a modular architecture, ensuring separation of concerns and code reusability.

Folder Breakdown

  • src/: Contains the main source code of the application.
    • modules/: Each feature is encapsulated within its module, following a modular design pattern.
    • common/: Houses reusable utilities such as decorators, filters, interceptors, middlewares, and pipes.
    • app.controller.ts: Root application controller.
    • app.module.ts: Root module where other modules are imported.
    • app.service.ts: Global application service.
  • test/: Contains unit and end-to-end tests.
  • config/: Stores configuration files for environment settings.
  • dist/: Compiled output directory (ignored in version control).
  • node_modules/: Dependencies.
  • package.json: Project dependencies and scripts.
  • tsconfig.json: TypeScript configuration.
  • .eslintrc.js, .prettierrc: Linting and formatting configuration.

Naming Conventions

A consistent naming convention ensures clarity and predictability in code structure.

File Naming

  • Modules: Use lowercase and hyphen-separated names, e.g., users.module.ts.
  • Controllers: Use plural form and include controller, e.g., users.controller.ts.
  • Services: Use singular form and include service, e.g., users.service.ts.
  • Entities: Singular PascalCase, e.g., User.entity.ts.
  • DTOs (Data Transfer Objects): Use dto suffix, e.g., create-user.dto.ts.
  • Middleware: Use middleware suffix, e.g., auth.middleware.ts.
  • Interceptors: Use interceptor suffix, e.g., logging.interceptor.ts.
  • Pipes: Use pipe suffix, e.g., validation.pipe.ts.
  • Guards: Use guard suffix, e.g., auth.guard.ts.
  • Filters: Use filter suffix, e.g., exception.filter.ts.

Class Naming

  • Modules: PascalCase, e.g., UsersModule.
  • Controllers: PascalCase, e.g., UsersController.
  • Services: PascalCase, e.g., UsersService.
  • Entities: PascalCase, e.g., User.
  • DTOs: PascalCase, e.g., CreateUserDto.
  • Middleware: PascalCase, e.g., AuthMiddleware.
  • Interceptors: PascalCase, e.g., LoggingInterceptor.
  • Pipes: PascalCase, e.g., ValidationPipe.
  • Guards: PascalCase, e.g., AuthGuard.
  • Filters: PascalCase, e.g., ExceptionFilter.

Best Practices

  1. Use Modules for Separation of Concerns: Keep each feature encapsulated within its module.
  2. Follow Consistent Naming Conventions: This improves readability and maintainability.
  3. Group Related Files: Keep DTOs, entities, and related files within the respective module directory.
  4. Use DTOs for Data Validation: Ensure input validation using DTOs and class-validator.
  5. Utilize Nest.js Built-in Features: Use decorators, pipes, interceptors, and guards effectively.
  6. Write Unit and Integration Tests: Keep tests organized in the test/ directory.

By following these conventions, your Nest.js project will be well-structured, scalable, and easier to maintain. Happy coding!
