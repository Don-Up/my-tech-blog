Changes to API Routes in Next.js App Router

2024-01-23
#API-Routes
Next.js

In Next.js App Router (app/ directory), API Routes from the Pages Router (pages/api/) are replaced with Route Handlers inside app/api/. This change brings a more modern, flexible, and edge-optimized API approach.

✅ Key Differences Between API Routes (Pages Router) & Route Handlers (App Router)

Feature Pages Router (/pages/api/) App Router (/app/api/)
File Location /pages/api/*.js /app/api/route.ts (or /app/api/[param]/route.ts)
Request Handling Uses (req, res) => {} like Express.js Uses Request & Response Web API
Supports Edge Functions ❌ No ✅ Yes (by default)
Middleware Support ❌ Limited ✅ Full support
Method-based Exports ❌ No ✅ Yes (GET, POST, PUT, etc.)
Streaming Responses ❌ No ✅ Yes (with React Server Components)

🚀 Summary: What Changed in API Routes?

Feature Pages Router (/pages/api/) App Router (/app/api/)
Uses File-Based Routing ✅ Yes ✅ Yes
How to Handle Methods if (req.method === "GET") Separate functions (GET(), POST())
Dynamic API Routes ✅ Yes (/pages/api/[id].js) ✅ Yes (/app/api/[id]/route.ts)
Query Parameters req.query new URL(req.url).searchParams.get("param")
Streaming Responses ❌ No ✅ Yes
Edge Optimized ❌ No ✅ Yes (by default)

🎯 Conclusion: Why Use Route Handlers in App Router?

✅ Better Performance: Supports Edge Functions for faster execution.
✅ Simpler API Design: No need for req.method; just use GET(), POST(), etc.
✅ Streaming Responses: Send data progressively for better UX.
✅ Full Middleware Support: Works well with Next.js middleware.

🚀 If you’re using the App Router, replace /pages/api/ with /app/api/route.ts!
