How is react useRef implemented

Foreword

in React development, useRef is a very important Hook for creating mutable reference containers that hold references to DOM elements or arbitrary values. Compared to the state, useRef it has the feature of not causing component re-rendering when modified, and is often used to access DOM, save variables, and achieve data persistence across rendering cycles. Understanding useRef the implementation principle of the, help to grasp the React Hook design ideas and component rendering process.

This article will explain in detail from the perspective of React’s internal mechanism. useRef implementation principle, as well as its application and attention points.

1. Basic usage and function of useRef

useRef takes an initial value and returns a .current property, which remains constant throughout the life of the component.

useRef key roles include:

  • access and manipulate DOM nodes.
  • Maintaining variable values during rendering cycles without triggering re-rendering.
  • Save non-rendering related data such as timer id and external subscription.

2. How to implement useRef inside React

2.1 The hook list on the Fiber node.

React uses the Fiber architecture to manage the rendering state of components, and the Hooks information is also stored in the linked list structure of the corresponding Fiber node. The execution of each function component will follow this hook list to ensure that the call sequence and status of hooks are correctly matched.

2.2 useRef creation and update process

  • when the component executes for the first time, useRef A new hook object is created in the hook linked list of the current Fiber node, with the following contents:
  • memoizedState used to save the state data of the hook, useRef the returned object is this memoizedState .
  • During subsequent rendering, React reuses the hook node and directly returns the previously stored memoizedState , which guarantees the constancy of the referenced object.

2.3 compared to different useState

with useState different, useRefDoes not participate in triggering component re-rendering. It holds object references that remain unchanged throughout the life of the component, modifying current property does not cause the component to update. This is determined by the React scheduler and the update mechanism of Fiber.

4. The essence of useRef: maintain constant references and variable content.

useRef the returned object reference is constant, but its internal .current properties are mutable. This design brings the following benefits:

  • the component gets the same object every time it is rendered, avoiding unnecessary re-creation.
  • Modification .current it does not trigger re-rendering and is suitable for saving data that does not affect UI.
  • By .current access and update data to share data across rendering cycles.

5. Use attention points and common misunderstandings

  • do not useRef used to save states that will affect UI rendering, should be used. useState .
  • Modification .current re-rendering will not be triggered, and other means should be used when manually triggering the update.
  • useRef any type of value can be saved, not limited to DOM nodes.

Interview answer

useRef is the Hook provided by React to create a variable reference object whose reference remains unchanged during the life cycle of the component, and its .current properties can be modified. React is stored and managed through the hook linked list on the Fiber node. useRef the object is created during the first rendering, and the same object is reused for subsequent rendering. With useState different, modify .current does not trigger component updates and is suitable for holding persistent data across render cycles or referencing DOM nodes.

Summary

useRefThrough the design of the hook list in the Fiber architecture, it ensures that the returned reference object remains stable between multiple renderings, while allowing .current make free modifications without triggering re-rendering.

Its core advantage is the implementation of state isolation and persistence, so that developers can easily operate the DOM and save the state does not affect the UI. Understanding useRef the implementation mechanism of the component is helpful to choose the state management method reasonably in the actual development, and improve the performance and maintainability of the component.
