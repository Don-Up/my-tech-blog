Is the process for ES5 and ES6 to instantiate objects using the new keyword the same

Foreword

in JavaScript, new keyword is an important tool for creating object instances. With the introduction of ES6, new class grammar, many people will question: ES5 era uses constructor coordination new and in ES6 class binding new is the instantiation process the same? This article will compare the execution process of the two in detail to help understand ES6. class the essence.

ES5 instantiation process using constructor and new

in ES5 and before, instantiating objects is usually coordinated through constructors. new keyword completed. Its processes include:

  • creates a new object and sets its [[Prototype]] pointing to the constructor prototype
  • execute the constructor, this point to New Object
  • Constructors implicitly return new objects (unless they explicitly return other objects)

at this point, the instance object inherits the properties and methods on the constructor prototype.

ES6 instantiation process using class and new

ES6 class the essence of is still syntactic sugar based on function and prototype chains, and its instantiation process is similar in nature to the ES5 constructor, with some additional restrictions and enhancements:

  • cannot be called new the class constructor is executed in the case of, otherwise an error is reported.
  • Strict mode is used by default inside classes to ensure safer syntactic behavior
  • class constructor must call super() (If there is inheritance), otherwise an error will be reported.
  • Method is defined in the class’s prototype on, and not enumerable

instantiation process steps:

  • create an instance object with the prototype pointing to the class’s prototype
  • binding this execute the constructor ( constructor method)
  • Returns an instance object or an object explicitly returned by a constructed function

main difference points

  • strict mode is on by default
    the ES6 class internal code automatically enables strict mode, and the ES5 constructor defaults to non-strict.
  • Call Limits
    the ES6 class must pass new call, otherwise throw an error; The ES5 constructor is not mandatory.
  • Inheritance mechanism
    ES6 class support built-in extends and super keyword, simplify the inheritance chain call, ES5 need to manually set the prototype chain and call the parent constructor.
  • Method Definition Properties
    methods in ES6 class are not enumerable by default, and prototype methods in ES5 constructor are enumerable.
  • More standardized syntax and semantics
    the ES6 class syntax is closer to traditional object-oriented languages.

Summary

from the core steps of the instantiation process, ES5 and ES6 use new the object creation mechanism is the same: both create new objects, bind thisExecutes the constructor, returns the object. The differences are mainly reflected in the limitations of ES6 class syntax, security and inheritance mechanisms. The ES6 class is essentially syntactic sugar and canonical boosting of the ES5 constructor.
