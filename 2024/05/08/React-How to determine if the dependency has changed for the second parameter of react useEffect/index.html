How to determine if the dependency has changed for the second parameter of react useEffect

Foreword

in The React function component, useEffect is the core Hook that performs side effects. Its second argument-the dependency array-determines when the side-effect function is executed.

Understanding how React determines whether dependencies have changed is critical to writing components that perform well and behave as expected. This article will be a detailed analysis of React in useEffect rely on the mechanism and principle of change judgment.

useEffect The role of the second parameter

useEffect receives two parameters:

the second parameter is an array that lists the variables on which the side-effect function depends. React compares the content of the dependency array passed in this rendering with that of the previous rendering to determine whether there is any change, and then determines whether to re-execute the side effect.

The role of dependent arrays is to control the execution frequency of side effects and avoid unnecessary repetition.

How does React determine whether a dependency has changed

React internal By contrast A reference to each element in the dependent array decide whether the dependency changes. The specific process is as follows:

  1. initial Render
    React will save the initial value of the dependent array, and the side effect must be executed.
  2. Subsequent Rendering
    React compares the currently rendered dependency array with the last saved dependency array (shallow compare).

The rule for shallow comparisons is to compare the references of each dependency for equality ( Object.is or similar equivalent comparisons).

  1. Judgment result
  • if all references to dependencies are the same as the last one, React considers the dependencies unchanged and does not execute side effects.
  • As long as there is a different dependency reference, the dependency is considered to have changed, side effects are performed, and the cached dependency array is updated.

Focus

React to judge the dependency change is reference Address not a deep comparison. This means:

  • basic types (string, number, Boolean) If the value is different, the reference is also different, and the side effect can be triggered correctly.
  • Reference types (objects, arrays, functions) will trigger side effects even if the content is the same, but the reference address changes.
  • If the dependency is a newly created object or function, each rendering is treated as a change.

How to Avoid Unnecessary Dependent Changes

  1. using useMemo or useCallback
    cache the function or object to avoid generating new references every time you render.
  2. Split dependency, refine dependency array
    if you only depend on certain fields of the object, try to rely only on the values of those fields, not the entire object.
  3. Handle anonymous functions or new objects with caution
    avoid writing anonymous functions or new objects directly to dependent arrays.

React in useEffect the second parameter of the dependency array determines whether the dependency has changed by shallow comparison (reference equality). It will compare the references of each element in the dependency array passed into the current rendering and the last rendering. If all references are the same, the side effect will not be executed. As long as one reference is different, the side effect function will be executed. Note that React does not perform deep comparisons, so a reference type dependency will trigger side effects even if the content is the same but the reference changes.

Summary

useEffect the dependency array of the second parameter is an important mechanism for React to control the execution of side effects. React determines whether the element references in the dependency array have changed by shallow comparison. Understanding this can help us avoid performance issues caused by frequent changes in dependencies. Rational Use of caching means (e. G. useMemo , useCallback ), splitting dependencies can effectively reduce unnecessary side effects, thereby optimizing component performance and behavior.
