The differences and principles between HashRouter and BrowserRouter in react Router

Foreword

in The React single-page application, the implementation of routing is the key to building a good user experience. As the most mainstream routing library in the React ecosystem, React Router provides a variety of routing containers. BrowserRouter and HashRouter . Understanding the differences between the two and the principles behind them will help developers choose the appropriate routing scheme according to the project requirements, thereby improving the stability and compatibility of the application.

This paper will analyze in depth BrowserRouter and HashRouter the core differences, implementation principles, and applicable scenarios, combined with code examples and tables to help understand.

The Principle of HashRouter

HashRouter browser-based URL hash changes implement routing. In the URL. #The part after the number is called a “hash fragment”, which is not sent to the server by the browser and therefore does not cause the page to refresh.

HashRouter the working principle is to listen to the browser. hashchange event, when window.location.hash when the change is made, The React Router matches the corresponding component according to the new hash path and renders it.

Third, the principle of BrowserRouter

BrowserRouter take advantage of HTML5’s History API (including pushState , replaceState and popstate event) to manipulate the browser history to implement route jumps without refreshing the page.

It is based on the path name of the browser ( window.location.pathname) to match, when the user switches pages, BrowserRouter will call history.pushState modify the address bar path, but do not trigger a page refresh, and trigger the React Router internal listening event to render the corresponding page.

Fourth, the choice of the two and the applicable scenario.

Which router to choose, mainly according to the project needs and server environment:

  • scenarios using BrowserRouter

  • the server can configure SPA route redirection (for example, nginx configures all paths to redirect index.html ).

  • Need beautiful URL, No. # symbol.

  • Focus on SEO and browser history management.

  • Scenarios using HashRouter

  • the server cannot configure redirection, or the access path causes a 404.

  • Compatible with older browsers or specific environments (for example, GitHub Pages only supports static file hosting).

  • The project does not pay attention to SEO, and the URL contains # does not affect the user experience.

Summary

BrowserRouter and HashRouter are two common routing containers in React Router. The core difference lies in the path management mechanism. BrowserRouter relying on HTML5 History API, the path is beautiful but requires the server to support redirection; HashRouter using the hash part of the URL has good compatibility and does not require server support, but the URL is not beautiful and SEO is poor.

Understanding the principles and advantages and disadvantages of the two is helpful to select the appropriate routing strategy for the specific project environment and achieve stable and efficient front-end routing management.

Interview answer

question: What is the difference between HashRouter and BrowserRouter In React Router? What is their principle?

Answer: BrowserRouterUse the HTML5 History API to operate the browser’s pushState and replaceState to manage the URL path and switch routes without refresh. Its URL is in the normal path format, which is suitable for production environments with server configuration support. However, when refreshing the non-root path, the server needs to be redirected to the entry file, otherwise 404 will occur.

HashRouter browser-based URL hash ( # ) Change to achieve routing, will not send requests to the server, so no server configuration is required, and compatibility is good. The URL has # not friendly to SEO.

In general, if the server is configurable with redirection, you recommend use BrowserRouter ; If the server has more restrictions or high compatibility requirements, you can use HashRouter .
