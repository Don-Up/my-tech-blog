How does fiber achieve interruptible updates

Foreword

in the traditional React rendering mechanism, the update process is synchronous and uninterruptible, which means that once the update is started, until all updates are completed, the main thread is occupied and cannot respond to user interaction or perform other tasks. This mode is easy to cause page jam and affect user experience when complex UI or large-scale updates are made.

One of the core goals of the Fiber architecture is to achieve “interruptible updates”, that is, the ability to pause execution during rendering, switch to other higher priority tasks, and then resume at the appropriate time to continue to complete the update. This article will elaborate on how Fiber implements the interruptible update mechanism, core data structure, scheduling process, and implementation details to help readers understand the key role of Fiber in improving rendering flexibility and performance.

What is an interruptible update?

Interruptible update means that the rendering task can be actively suspended during execution, releasing the main thread, giving up execution power to more urgent tasks (such as user input and animation), and then resuming the remaining rendering work at the right time to ensure system responsiveness and smooth experience.

In React Fiber, this means that React can dynamically decide when to pause the current update and when to resume based on the task priority and the browser’s idle time, thus enabling smarter scheduling.

The key mechanism for implementing interruptible updates by Fiber

1. Fine-grained task splitting – Fiber unit task

the Fiber architecture splits the entire rendering update into a “unit of work” (unit of work), with each Fiber object corresponding to a unit of work, representing the rendering coordination of a node in the virtual DOM tree.

This splitting granularity is small enough to actively check whether it needs to be interrupted after the unit task is executed.

2. Task chain table structure, easy to suspend and resume

the Fiber node passes through child , sibling , return the pointers are concatenated into a tree structure, which is traversed by a linked list during execution.

By saving the currently executing Fiber node pointer (that is, the next execution unit), you can interrupt the task at any time and resume execution from the breakpoint when you resume later.

3. Browser idle time scheduling.

React combines the browser’s idle time API (such requestIdleCallback ) or a timestamp-based scheduling mechanism to determine whether the current time slice is sufficient.

If it is found that the remaining idle time is insufficient, it will actively suspend execution and release the main thread.

4. The priority mechanism drives the scheduling strategy.

Fiber designs a complex priority scheduling system that assigns different types of tasks to different priorities.

When a higher priority task enters, the update of the current lower priority can be interrupted, and the high priority task is executed preferentially to ensure that the key interaction is not stuck.

Fiber interrupts the updated scheduling process

  1. start coordination
    React starts from the root Fiber and executes the first unit task.
  2. Execute Unit Tasks
    call performUnitOfWork(fiber) completing the coordination task for the current node may generate or update sub-fibers.
  3. Determine whether interruption is required
    after each unit task is executed, the current remaining time is checked (using deadline.timeRemaining() ) and task priority to determine whether a pause is required.
  4. Save Current state
    if you need to interrupt, save the current Fiber node pointer and pause subsequent tasks.
  5. Release the main thread
    call the browser’s callback registration function ( requestIdleCallback ), waiting for the next idle time to resume scheduling.
  6. Resume execution
    when the next idle time comes, the last saved Fiber pointer continues to execute the unfinished task.
  7. Complete coordination
    after all Fiber nodes are coordinated, the real DOM is updated in the synchronous Commit phase.

Advantages of Fiber interruptible updates

  • avoid the main thread blocking for a long time improve application response speed and fluency.
  • Support task priority switching to ensure that key interactions are prioritized.
  • Improve resource utilization adapt to complex and changeable rendering scenes.
  • Lay the foundation for The React concurrency model to enable more complex asynchronous rendering capabilities.

Interview answer example

question: How does React Fiber implement interruptible updates?

Example answer:

React Fiber splits the update task into fine-grained unit tasks (corresponding to each Fiber node) and cooperates with the browser’s idle time API (such requestIdleCallback ), which enables interruptible execution of rendering tasks.

After each unit task is executed, Fiber will check the remaining time and task priority. If the time is insufficient or a higher priority task enters, it will actively suspend the current task and save the execution status. After that, the unfinished tasks are resumed in the next idle time of the browser. This interruptible mechanism avoids the main thread being occupied for a long time, improves the interface response speed, and supports flexible priority scheduling.

Summary

Fiber implements interruptible updates of rendering tasks through fine-grained task splitting, linked list structure to save execution state, combined with browser idle time scheduling and priority scheduling. This mechanism not only solves the problem that traditional React rendering blocks the main thread, but also greatly improves the responsiveness and user experience of the application.

Interruptible updates are one of the core capabilities of React Fiber and the basis for React’s future asynchronous and concurrent rendering modes. Understanding how Fiber implements interruptible updates helps developers gain insight into the React rendering scheduling mechanism and provides theoretical support for building high-performance applications.
