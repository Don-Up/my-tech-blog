What is the difference between Object.is() and the comparison operators ‘===’, ‘= =‘

foreword

when comparing values in JavaScript, common operators are the strict equality operator ( === ), abstract equality operator ( = = ), and the introduction of ES6 Object.is() methods. They are ostensibly used for comparison, but there are subtle differences in specific behavior and semantics. This paper analyzes the differences between the three and their respective application scenarios.

The basic difference between the three

1. = = (Abstract equality operator)

= = A type conversion (type casting) is performed during the comparison, and then the values are compared. Because it will be converted automatically, it may lead to some unexpected results.

2. === (Strict equality operator)

=== no type conversion, required type and value are the same before returning true .

3. Object.is()

Object.is() used to determine whether two values are strictly equal, similar === but there are two special ones:

  • distinction +0 and -0 , Object.is(+0, -0) return false , and +0 === -0 return true .
  • Think NaN and NaN are equal, Object.is(NaN, NaN) return true , and NaN === NaN return false .

summarize the difference

  • = =Allows conversion comparison between different types, which is prone to implicit type conversion errors and is not recommend in strict code.
  • === requires the type and value to be exactly the same, but put +0 and -0 treated as equal NaN regarded as unequal.
  • Object.is() suitable for the need to distinguish +0 , -0 , and correct judgment NaN the same scene.

summary

understanding the differences between the three can help developers choose the correct comparison method, avoid the errors caused by implicit type conversion, and improve the reliability and accuracy of the code.
