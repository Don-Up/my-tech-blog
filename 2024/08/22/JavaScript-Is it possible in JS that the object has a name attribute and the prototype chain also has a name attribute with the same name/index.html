Foreword

the object system in JavaScript supports the inheritance mechanism, where the prototype chain is the core of the implementation of inheritance. Since an object and its prototype chain can have their own properties, there may be situations in reality where the object itself and its prototype chain have properties of the same name. This article will focus on the question of “whether the object itself and the prototype chain can have the same name attribute” for in-depth analysis.

Attribute Override and Same Name Attribute Mechanism

the attribute search in JavaScript is a “bottom-up” mechanism: that is, starting from the object itself, searching for its prototype if it cannot be found, and then searching for the prototype of the prototype Object.prototype so far.

If an object has a property of its own, even if its prototype chain also has a property of the same name, the object’s own property will be used first when accessing. This phenomenon is called property shadowing or property overwriting “.

Interview answer demonstration

question: Is it possible in JS that the object itself has a name attribute and the prototype chain also has a name attribute with the same name? If so, what happens?

Example answer:

“It is entirely possible. In JavaScript, Property lookup is done through the prototype chain, if the object itself has a property, such. name , then even if a property with the same name exists on the prototype chain, only the property of the object itself will be returned when accessed. This is called attribute override or attribute masking.

That is, the object’s name the property masks the property of the same name on the prototype chain, and the value on the prototype will not be used until the property of the object itself is deleted.”

summary

the property of the same name between the object and the prototype chain in JavaScript is not a conflict, but a common phenomenon under the inheritance mechanism. The properties of the object itself take precedence over the properties of the same name on the prototype chain, forming the so-called “property mask”. Understanding this mechanism helps us to control object behavior more clearly, avoid misreading attribute sources, and provide a technical basis for debugging complex inheritance relationships.
