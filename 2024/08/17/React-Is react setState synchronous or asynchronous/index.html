Why is setState asynchronous?

React’s asynchronous updates are designed to improve performance. Imagine a situation where:

if every time setState both update synchronously and trigger re-rendering, performance will be extremely poor. React will merge these updates and process them in the next rendering, reducing unnecessary calculations and DOM operations.

Therefore, setState the “asynchrony” is part of React’s performance optimization strategy.

The asynchronous representation of setState is environment dependent

React in setState the asynchrony of depends on the context in which it is running. Can be roughly divided into the following:

1. React-controlled environment ( asynchronous )

  • synthetic events (e. G. onClick, onChange)
  • lifecycle methods (such as componentDidMount)

2. Native event/setTimeout / Promise ( synchronization)

Interview answer: is setState synchronous or asynchronous In React?

React in setStateThe call to is executed synchronously, but the status update itself is done asynchronously. This asynchrony comes from React’s batch mechanism, which is designed to optimize performance. In the Lifecycle methods and synthetic events of React, setState is usually asynchronous, while in setTimeout or native events, it may be synchronous.

However, starting with React 18, the automatic batching mechanism has been extended to all environments, making most setState the behavior is all uniform asynchronous.

To avoid state read errors, recommend use functional setState and use the callback function when you need to listen for the update to complete.
