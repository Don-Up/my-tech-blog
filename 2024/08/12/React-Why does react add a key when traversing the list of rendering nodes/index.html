Why does react add a key when traversing the list of rendering nodes

Foreword

when using React to build a front-end interface, developers often need to batch render a list of components or elements by traversing the data. At this point, React requires the developer to provide a unique for each list item. key property. If omitted key or make improper choices, such as using array subscripts, React will prompt warnings and may cause rendering efficiency or status errors.

Many beginners may wonder why React must be added. key what? What is the role of this property? This article will explain in depth key the essential meaning, the mechanism behind it, the correct way to use it and common misunderstandings.

key the essential role of: unique identification and performance optimization

React uses the virtual DOM + diff algorithm to efficiently update the view. When the state changes, React determines which nodes need to be updated, reused, inserted, or deleted by comparing the differences between the new virtual DOM tree and the old virtual DOM tree.

When comparing two node lists, if there is no key , React will use a sequence comparison the strategy of comparing each node by location from beginning to end. This strategy can easily lead to insertion, deletion, or reordering of list data:

  • Nodes are not reused, resulting in unnecessary unloading and mounting operations
  • too many DOM operations, reducing performance
  • state dislocation, resulting in abnormal UI behavior

in order to more accurately determine which nodes are “the same”, React requires developers to provide key as the unique identity of each node. key the existence of can significantly improve the accuracy of diff comparisons and avoid meaningless re-rendering or state confusion.

key it is the core means of identifying nodes within React.

React’s diff process is essentially a one-to-one match between the nodes in the old Fiber tree and the new Fiber tree, and the matching strategy mainly depends on three points:

  1. is the node type consistent (for example, div and span are different types)
  2. key whether the same
  3. if the above two are the same, they are considered “the same node” and can be reused and updated

therefore, key directly determines the “identity” of the node “. If key React unmounts the old nodes and remounts the new nodes, even if their contents are exactly the same.

common Mistake: Using Array index as key

although using index as the key will not report an error, it will cause problems in the following scenarios:

  • The order of the list data changes (such as sorting, inserting, deleting)
  • list items contain stateful components (such as input boxes, animations, etc.)

this is because index is the identity of the location rather than the real identity of the node. Once the order changes, React’s diff algorithm will misjudge, resulting in reuse errors.

Interview answer: Why does React need to add key to traverse nodes?

Answer:

React needs to be added when rendering the node list. key is improving the efficiency and correctness of the diff algorithm . When React compares the old and new Virtual DOM, it will pass key determine which nodes can be reused and which need to be inserted or deleted.

If not added key , or use unstable keys (such as array subscripts). When the list data changes, inserts or deletes in sequence, React may not be able to correctly identify nodes, resulting in incorrect reuse or destruction of components, resulting in performance problems and UI state disorder.

The correct approach is to use a unique value (such as id) that can stably represent the identity of the item in the list. key in this way, React can accurately and efficiently handle node changes.

Summary

add unique and stable for list render items in Reactkey it is a fundamental requirement in the development process, but behind it lies a profound impact on the efficiency of the Virtual DOM diff and the consistency of the UI state.

Reasonable Use key can:

  • improve rendering performance and reduce DOM operations
  • accurately preserve component state to prevent UI exceptions
  • provides a stable node identity for React and supports a more efficient diff policy

in actual development, avoid the use of index as the key, give priority to the use of business-related unique identifiers, in order to truly take advantage of the React architecture design. Understanding key the principle of helps you write more efficient and robust front-end applications.
