What’s the difference between the coordination stage and the submission stage

Foreword

the rendering process of React is a complex and efficient process, especially after the introduction of the Fiber architecture, the entire update process is divided into two core phases: the coordination Phase (Render Phase) and the Commit Phase (Commit Phase). These two stages perform their own duties in the React update process, are responsible for different tasks, and complement each other to complete the efficient update of UI.

Understanding the difference between the coordination phase and the commit phase is important for understanding the internal rendering mechanism of React, debugging performance issues, and writing efficient React code. This article will systematically explain the responsibilities, execution methods, performance impact and specific details of these two stages to help readers establish a clear understanding.

Render Phase

the main task of the coordination phase is to compare the old and new Virtual DOM trees, generate the description of the changes required for the update, and build a new Fiber tree, but this phase do not modify the real DOM .

Specific Duties

the coordination phase will:

  • recursively traverse the current Fiber tree and compare the old and new Fiber nodes to find out which nodes need to be created, updated or deleted.
  • Generates an Effect List (side Effect List), marking the operations that need to be performed, such as INSERT, UPDATE, delete, etc.
  • Calculating state updates for components, calling Lifecycle methods (e. G. render , getDerivedStateFromPropsEtc.) to generate a new React element tree.

Key Features

  • interruptability : The coordination phase can be interrupted and resumed, using time slicing techniques to avoid blocking the main thread.
  • Pure calculation process : does not produce any side effects, does not operate DOM, does not trigger browser redraw.
  • Performance friendly : It can be completed by using the browser’s idle time to improve responsiveness.
  • Stage failure can be rolled back : If the coordination fails (such as an error is thrown), the real DOM will not be affected and you can try again.

The Commit Phase

the commit phase follows the reconciliation phase and is responsible for synchronizing the changes prepared by the reconciliation phase to the real DOM, as well as performing all side-effect operations.

Specific Duties

the submission phase includes:

  • according to the Effect List, insert, update, and delete the real DOM.
  • Execute side effects in The React lifecycle hook, such componentDidMount , componentDidUpdate .
  • Call useEffect anduseLayoutEffect the callback function corresponding to the hook.
  • Triggers browser repaint and reflow.

Key Features

  • synchronous execution, non-interruptible : once the commit phase starts, it will be executed synchronously to avoid inconsistent UI states.
  • Execution side effects : The only phase that allows modification of the real DOM and external environment.
  • Performance Key Points : The time-consuming submission phase will directly affect the page frame rate and user experience.

interview answer example

question: Please briefly describe the difference between the reconciliation phase and the commit phase in React.

Example answer:

the React rendering update process is divided into a coordination phase and a commit phase. The coordination phase is responsible for traversing the old and new Fiber trees, calculating differences, and generating change descriptions, but does not operate the real DOM and is an interruptible asynchronous process. The commit phase is responsible for synchronizing these changes to the real DOM, executing lifecycle hooks and side effects, and is a synchronous and uninterruptible process.

The coordination phase is mainly about calculation and preparation, focusing on performance and responsiveness. The submission phase is the final effective operation to ensure that the UI is consistent with the data.

Summary

The coordination phase and the submission phase are the two core tasks of React rendering, and they are responsible for calculating and applying changes respectively. In the coordination phase, the construction and change marking of the Fiber tree are completed in an interruptible and purely computational manner, while in the commit phase, the real DOM is updated synchronously and side effects are executed to ensure the final consistency of the UI.

Understanding the difference and coordination between the two stages helps to better understand the internal working principle of React, optimize performance, and make accurate judgments when debugging complex problems.
