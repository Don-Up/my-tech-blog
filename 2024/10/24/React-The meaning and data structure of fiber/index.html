The meaning and data structure of fiber

Foreword

in the modern front-end framework React, Fiber is the core architecture introduced by React16. It fundamentally reconstructs the rendering and scheduling mechanism of React, greatly improving the flexibility and performance of rendering. Understanding the meaning of Fiber and its underlying data structure is essential for understanding the working principle of React, optimizing performance, and debugging complex applications. This article will detail the concept of Fiber, its design intent and its data structure to help readers build a systematic understanding.

The meaning of Fiber

A Fiber is a work unit in React that describes each node in the component tree. It carries the component’s state, properties, and scheduling information during rendering. A Fiber can be understood as an “enhanced version of a virtual DOM node”, which not only represents a component structure, but also includes support for scheduling.

The core goal of the Fiber mechanism is to enable React’s rendering process to be “interruptible”, “recoverable”, and “task priority scheduling. Traditional React rendering is synchronous and blocking, and once you start rendering, you can’t respond to other tasks until you finish. Fiber achieves asynchronous rendering by subdividing tasks and maintaining state, enabling the browser to respond to user interactions in a timely manner, improving the response performance of the application.

In simple terms, Fiber is a set of internal data structures and scheduling mechanisms designed by React to implement asynchronous incremental rendering.

the original design intention of Fiber

In React15 and previous versions, the traversal and update of the component tree are performed recursively and synchronously. When the recursion depth is large, it is easy to cause stack overflow, and the rendering process blocks the main thread, and the user interaction experience is poor. To overcome these problems, The React team designed the Fiber architecture to meet the following requirements:

  • asynchronous Interruptible Rendering : Split the rendering task into multiple small fragments, and the browser main thread can interrupt the execution to ensure that high-priority tasks (such as user input) are executed first.
  • Task priority scheduling : Dynamically adjust the execution order according to the importance of the task.
  • Avoid recursive calls : Use a linked list data structure instead of recursive traversal to Reduce stack risk.
  • Track side effects and status changes : Clearly record which nodes need to be updated, inserted or deleted, which is convenient for batch processing.

Data Structure of Fiber

A Fiber is essentially a node object in a linked list structure that represents the corresponding component or element in the component tree. Each Fiber node contains rich fields for storing the component’s type, properties, status, and scheduling and side effect information. A typical Fiber node structure is as follows:

field Name description
type node type, such as DOM tag name or React component type
key unique identifier, used to distinguish nodes in the list.
stateNode Associated real DOM or component instance
return point to parent Fiber node
child pointing to the first child Fiber node
sibling point to the next sibling Fiber node
pendingProps new props that will be applied when rendering
memoizedProps props currently in effect
memoizedState current Effective Status
updateQueue update queue, which stores pending status updates
effectTag side effect tag, which identifies the operation (such as update, delete) that the node needs to perform
nextEffect the next Fiber node with side effects in the linked list

between Fiber nodes through child , sibling and returnThe three pointers form a tree structure. Unlike the simple tree structure of traditional Virtual DOM, Fiber allows pause, resume, and priority scheduling during traversality.

Fiber linked list diagram

  • Fiber A of child point Fiber B , Fiber B of sibling point Fiber C .
  • Fiber B of child point Fiber D , Fiber C of sibling point Fiber E .
  • Each Fiber passed return pointer points to the parent node to implement a doubly linked list.

Brief Description of Fiber Workflow

When React updates, a new Fiber tree (work-in-progress tree) is first built, and then the differences between the old and new Fiber nodes are compared one by one, marking the nodes that need to be updated (set effectTag ), the final submission phase uniformly executes these side effects to update the real DOM.

The linked list structure and task splitting of Fiber allow the update process to be interrupted or switched to support more complex task scheduling and better performance.

Summary

Fiber is the core of the underlying architecture introduced by react16. it is the work unit of each node in the React component tree and combines component information and scheduling control. It implements incremental traversal of the tree through a linked list structure and supports asynchronous interruptible rendering and task priority scheduling. The design of Fiber not only solves the problems of recursive call depth and main thread blocking in previous versions, but also brings more flexible and efficient rendering capabilities to React. A thorough understanding of the data structure and working principle of Fiber helps you better understand the performance optimization and source code reading of React.

the interview answer

question: What is the meaning and data structure of Fiber?

Answer:

Fiber is a new coordination algorithm and data structure introduced by React16, which represents the “unit of work” of each node in the component tree “. It not only contains the type, properties, and state information of the component, but also carries the scheduling and side effect tags. Fiber is organized into a tree through a linked list structure (child, sibling, return pointer) to achieve interruptible and recoverable asynchronous incremental rendering. The design of Fiber solves the problem of blocking the main thread of React15 recursive rendering, supports task priority scheduling, and makes the rendering process more flexible and efficient. The key fields in the Fiber structure include type , stateNode , pendingProps , memoizedState , effectTag etc., it is convenient for React to track status changes and update DOM in batches.
